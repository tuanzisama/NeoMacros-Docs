---
title: "你的第一个脚本"
---

本页从零搭建一个完整的脚本：一个文件夹、一份清单、一个入口文件，以及把改动变成运行中代码、全程不用退出游戏的重载循环。

## 创建文件夹和清单

先挑一个与脚本触发方式匹配的类别目录。以事件驱动脚本为例，创建 `config/neomacros/macros/event/hello/`，并在其中放一份 `neomacro.yml` 清单：

```yaml
name: hello            # unique ID used by commands and the trust table
version: 1.0.0
author: you            # these three fields are required
description: greets you when you join a world

config:
  event:
    on: [world:join]   # the events this script reacts to
```

`neomacro.json` 也可以（同一文件夹下如果两者并存，`neomacro.yml` 优先）。顶层只放身份字段：必填的 `name`、`version` 和 `author`，以及可选的 `description`、`license`、`homepage`、`supportURL`、`main`（入口文件，默认 `index.js`）和 `permissions`（详见[权限与信任](./permissions-trust)）。

行为则放在 `config:` 块里。对事件宏来说，`config.event.on` 列出要响应的事件；事件名在加载时校验，写错立刻会被拒绝。

## 编写入口文件

在同一文件夹里创建 `index.js`：

```js
const { chat } = neo;

export function startup(payload) {
    chat.log('Hello from my first script!');
}
```

脚本就是一个普通的 ES 模块，NeoMacros 唯一强制要求的导出是 `startup`（支持 async）。对事件宏来说，声明的事件每发生一次就会调用一次 `startup(payload)`——传入的是手动 `events.on` 处理器能拿到的同一个快照对象。顶层代码仍在加载时执行一次，因此适合放常量和模块状态。

::tip
让你的编辑器指向已发布的 TypeScript 定义文件（`/neomacros.d.ts`），即可为每个 `neo.*` 成员获得自动补全和内联类型。
::

## 加载并验证

在聊天框里执行重载命令：

```text
/neomacros reload
```

然后确认脚本已经加载：

```text
/neomacros list
```

进入一个世界触发 `world:join`，就能看到问候语出现在本地聊天里。

## 了解错误出现在哪里

如果清单格式有误、事件名未知或缺少 `startup`，该文件夹会被跳过，原因会被记录下来。如果运行中的脚本抛出异常，错误会被捕获，其余脚本继续运行。这两类故障都会显示在 `/neomacros errors` 里，附带错误消息和指向你文件的堆栈跟踪——参见[排错指南](./troubleshooting)。

## 改用按键触发

`macros/keypress/<name>/` 下的脚本在清单里声明触发沿，而不是声明事件：

```yaml
config:
  keypress:
    on: keydown           # keydown / keyup / keypress (the default)
    default-key: key.keyboard.j
    modifiers: [ctrl]     # optional: require ctrl/shift/alt
```

每个触发沿都会调用 `startup(ev)`，其中 `ev = { event, key, code, clicks, modifiers }`，所以同样的入口写法依然适用：

```js
export function startup(ev) {
    neo.chat.log(`pressed ${ev.key}`);
}
```

`default-key` 只是建议值——它用来生成初始绑定，并不会把绑定锁死。

## 用 dispose 清理

模块加载期间创建的订阅会归属到该模块，并在卸载时自动移除，因此重载不会泄漏处理器。如果你的脚本还持有订阅之外的东西——一个定时器、一个来自 `neo.fs` 的文件句柄——就导出一个可选的清理钩子：

```js
export function dispose() {
    // extra teardown before the module is dropped
}
```

`dispose()` 在重载和卸载时运行，之后引擎会清除剩余的一切。接下来，让脚本对你周围的世界做出反应：阅读[事件系统](../api/modules/core/events)。
