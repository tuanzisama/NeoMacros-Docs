---
title: "权限与信任"
---

脚本运行在沙箱里。读取世界状态、输出聊天、绘制覆盖层、调度定时器永远被允许——这是基础表面。任何越过它的东西（文件、网络、命令、宿主 JVM）都必须由脚本声明、由你授予。

## 受门禁管控的能力

| 权限 | 解锁内容 |
| --- | --- |
| `fs` | `neo.fs` 的全部成员：`readText`、`writeText`、`readJSON`、`writeJSON`、`list`、`mkdir`、`delete` 等 |
| `net` | `neo.net` 的全部成员：`fetch`、`get`、`post` |
| `command` | `neo.command.register` 和 `neo.command.execute` |
| `java` | `neo.java`、`neo.reflect` 和 `neo.client.minecraft` |
| `packet` | 数据包构建面上的 `buffer.send()` 与 `buffer.toPacket()` |

前三项是范围受限的能力：授予 `fs` 只解锁相对于游戏目录的文件访问，别无其他。`java` 权限则不同——它授予完全的宿主访问且不做任何类过滤，因此它相当于最高级别的信任（参见 [Java 互操作](./java-interop)）。

## 清单中的能力声明

脚本用可选的顶层 `permissions` 字段声明自己的需求：

```yaml
# config/neomacros/macros/event/backup-notes/neomacro.yml
name: backup-notes
version: 1.0.0
author: you
description: keeps a running note file
permissions: ["fs"]

config:
  event:
    on: [chat:receive]
```

没有 `permissions` 列表（或列表为空）的脚本完全运行在基础表面上，永远不会触发授权提示。未知的能力名不会授予任何东西——拼写错误会直接失败（fail closed），而不是悄悄扩大访问范围。

## 授予信任

首次加载一个声明了能力的脚本时，会弹出确认对话框列出它请求的内容——与运行期请求使用同一个对话框，一次只弹一个（没有对话框系统的旧版本回退为聊天栏可点击行）。在你做出决定之前，脚本运行在"一律拒绝"的视图下——受门禁的调用会抛错。点击「允许」即授予信任；同一决定也可以手动下达，参数接受脚本名或请求 id：

```text
/neomacros permission allow backup-notes
```

拒绝或关闭不会留下任何记录——什么都不持久化，下次加载提示会重新出现。信任对运行中的脚本立即生效：受门禁的调用马上恢复可用，脚本不会重启、状态全部保留。

撤销（revoke）会移除脚本持有的全部授予——持久化的决定、本次会话的授予、以及本次会话的拒绝记忆——运行中脚本的受门禁调用在下次触发时立即重新抛错，无需重启：

```text
/neomacros permission revoke event:backup-notes
```

脚本参数接受 `{分类}:{名称}` 形式（`event:`、`keypress:` 或 `services:`），permission 系列命令与 `enable` / `disable` 都会自动补全。

信任决定以脚本的内容哈希为键，这带来两个结果：

- 编辑文件会改变哈希，因此已信任的脚本绝不可能悄悄长出新能力——提示会重新出现，改动经审阅后再次批准。
- 决定跨重启持久保存（存放在 `config.json` 里）。

改动后重新批准是正常工作流，提示本身就充当审阅步骤。

## 不受信任的脚本做不了什么

没有对应授予时，脚本：

- 无法通过 `neo.fs` 读写任何文件；
- 无法通过 `neo.net` 发起任何网络请求；
- 无法注册或执行客户端命令；
- 无法触碰 `neo.java`、`neo.reflect` 或 `neo.client.minecraft`。

基础表面的一切仍然可用：事件、定时器、聊天输出、世界与玩家读取、HUD 与渲染覆盖层，以及它自己的 `neo.storage` 存储。受门禁的调用在触发时抛错，错误会显示在 `/neomacros errors` 里——参见[排错指南](./troubleshooting)。

## 运行时申请权限

脚本可以通过 `neo.permissions` 查询门禁状态，并在运行时申请一个已声明的能力：

```js
if (!neo.permissions.checkPermission('fs')) {
    const granted = await neo.permissions.requestPermission('fs');
    if (!granted) {
        neo.chat.log('备份已停用：文件访问被拒绝');
        return;
    }
}
// 从这里开始 fs 门面可用
```

`requestPermission` 在清单未声明该能力（声明即上限）或能力名未知时 reject。已授予的能力立即解析；未授予的会弹出确认对话框（没有对话框系统的旧版本回退为聊天栏可点击行）。同意即持久信任整个脚本——与加载提示的「允许」是同一个脚本级决定——并且运行中的脚本立刻就能使用该能力，无需重启。拒绝或关闭解析 `false`，脚本自行决定如何降级。

## 最小权限原则

授予应只覆盖脚本真正用到的能力，声明更少的脚本更可取。信任一个不是你写的脚本之前，先读的是它的清单——`permissions` 一行准确说明了代码里该找什么。索要 `java` 的脚本值得通读一遍；什么都不索要的脚本可以直接运行。
