---
title: "MCP Agent 服务器"
---

NeoMacros 内置 [MCP](https://modelcontextprotocol.io)（Model Context Protocol）服务器。AI Agent——Claude Code、Codex、ZCode 或任意 MCP 客户端——通过 Streamable HTTP 连接进来，即可读取日志、检查游戏状态、操作客户端，底层复用脚本所依赖的同一套内部设施。本页覆盖启动、Agent 接入与三个日常场景。

## 准备条件

- 任意受支持版本的 NeoMacros jar（`1.21.6`、`26.1.2`、`26.2`、`26.3`），已安装并启动。
- 同一台机器上的 MCP Agent（服务器默认只绑定本机回环地址）。
- 游戏正在运行——状态与控制工具需要身处世界之中；日志类工具随时可用。

## 服务器的启动

服务器默认关闭。游戏内：

```
/neomacros mcp start
```

命令会打印 Agent 配置所需的全部信息：

```
MCP 服务器运行中，端口 30637（会话数：0）
端点：http://127.0.0.1:30637/mcp
Bearer 令牌：5cdccad103d9d99fbdbd27cc8d45f8ed
```

`/neomacros mcp stop` 停止；`token` 再次打印连接信息；`regen` 轮换令牌并断开所有现存会话。长期使用则由配置承载（`config/NeoMacros/config.json` 的 `core.mcp` 分区，或 ModMenu → NeoMacros 设置 → MCP Agent 服务器）：开启后，服务器随游戏启动。

::tip
令牌在首次启动时生成并持久化，重启不丢。一旦流入公开场合，`/neomacros mcp regen` 会立刻作废它。
::

## 用 curl 检查端点

一条 curl 往返就能证明服务器、端口、令牌三者正常：

```bash
curl -s -X POST http://127.0.0.1:30637/mcp \
  -H "Authorization: Bearer <令牌>" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"smoke","version":"0"}}}'
```

健康的服务器会应答 `serverInfo`（`"name":"neomacros"`）和一个 `Mcp-Session-Id` 响应头。连接被拒绝说明服务器没在运行（或端口不同）；401 说明令牌不匹配。

## Agent 接入

Claude Code：

```bash
claude mcp add --transport http neomacros http://127.0.0.1:30637/mcp \
  --header "Authorization: Bearer <令牌>"
```

其他所有 MCP 客户端要的都是同样两样东西：`/mcp` 上的 HTTP 端点，和 `Authorization: Bearer <令牌>` 请求头。接入后的第一步验证，是让 Agent *列出它可用的工具*——下表中的 `get_*`、`list_modules`、`send_chat` 等应当出现。

## 三个日常场景

**排查行为异常的脚本。** *"我的脚本里有个东西在刷错误——查一下 console 和日志，找出原因，告诉我要改哪个脚本。"*——这样的提示会让 Agent 去读 `get_console`（脚本输出，含 DevTools 会话）和 `get_logs`（按 logger 或级别过滤），定位堆栈，改文件前先用 `eval_script` 探一下运行时状态。脚本改完后，`stop_module` + `start_module` 重载脚本，再回看 `get_console` 确认修好。

**关于游戏的问题。** *"我在哪个维度、几点了、16 格内有什么怪？"* 对应 `get_world`（维度、时间、天气、按半径查实体）；*"我身上有什么？"* 对应 `get_player` + `get_inventory`（手持、槽位、以及打开中的容器）。`get_screen` 报告当前界面或对话框——Agent 协助操作菜单时很有用。

**代为操作。** 控制组开启后，Agent 可以 `send_chat`、`run_command`（等同在聊天栏输入 `/...`）、`inject_key`、管理脚本。一切都*以你的身份*执行——一条 `run_command` 与你亲手输入无法区分。`eval_script` 能力最强也最危险：任意 JavaScript 加完整 `neo.*` 访问，等价于一个完全受信的脚本。

## 工具一览

| 工具 | 组 | 作用 |
| --- | --- | --- |
| `get_logs` | 日志 | 日志行，按序号增量回放（`after`），支持级别与 logger 过滤。默认捕获 NeoMacros 日志；`logCapture` 设为 `all` 时捕获全量游戏日志。 |
| `get_console` | 日志 | 脚本 console 输出（`console.log` 等，含 DevTools 会话）。 |
| `get_network` | 日志 | `neo.net` 记录的请求：状态、耗时、请求/响应体预览。 |
| `get_tasks` | 日志 | 运行中的脚本任务与历史记录。 |
| `get_player` | 状态 | 本地玩家快照：位置、血量、饥饿、药效、护甲。 |
| `get_inventory` | 状态 | 手持物品、背包槽位，以及打开中的容器。 |
| `get_screen` | 状态 | 当前界面、打开中的对话框（含动作/输入项）、聊天框草稿。 |
| `get_world` | 状态 | 维度、时间、天气与半径内实体。 |
| `list_modules` | 控制 | 所有已发现脚本及其运行/启用状态与加载错误。 |
| `start_module` / `stop_module` | 控制 | 加载/卸载脚本（不改持久化的自启意图）。 |
| `send_chat` | 控制 | 以玩家身份发一条聊天消息。 |
| `run_command` | 控制 | 以玩家身份执行命令（等同在聊天栏输入 `/...`）。 |
| `inject_key` | 控制 | 注入一次原始按键按下/抬起。 |
| `eval_script` | eval | 执行 JavaScript，拥有完整 `neo.*` 访问能力——共享 DevTools 会话或指定脚本上下文。 |

客户端不在已加载世界中时，状态与控制工具返回 `isError` 结果；日志类工具随时可用。

## 安全模型

- **默认关闭。** 不启动（或不开 `autoStart`）就不监听任何端口。
- **回环绑定。** 监听器只应答 `127.0.0.1`，除非改动了 `core.mcp.listen`；无论哪种绑定，Host 与 Origin 校验都会拒绝 rebinding 尝试。
- **Bearer 令牌。** 首次启动自动生成并持久化到 `config/NeoMacros/config.json`，每个请求都必须携带。`regen` 轮换令牌并踢掉已连接会话。
- **分组开关。** `groupLogs`、`groupState`、`groupControl`、`groupEval` 关闭后整组工具从 `tools/list` 消失——`groupEval` 决定 Agent 能否执行任意 JavaScript。

## 配置参考（`core.mcp`）

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `enabled` | `false` | 上次启动/停止意图；服务器按此状态随游戏恢复。 |
| `autoStart` | `false` | 不论 `enabled` 与否，随客户端启动。 |
| `port` | `30637` | TCP 端口（Web 面板使用 30636）。 |
| `listen` | `127.0.0.1` | 绑定地址（`127.0.0.1`、`0.0.0.0`、`::1`）。 |
| `token` | *(自动生成)* | Bearer 令牌；留空则下次启动时生成。 |
| `logCapture` | `mod` | `mod` 仅捕获 NeoMacros 日志，`all` 捕获全部 logger。 |
| `groupLogs` / `groupState` / `groupControl` / `groupEval` | `true` | 工具分组开关。 |

## 排错

- **每个请求都 401。** Agent 请求头里的令牌与当前令牌不一致。`/neomacros mcp token` 可重新打印令牌供核对；若令牌曾泄露，`regen` 之后还要更新 Agent 配置。
- **对话中途 `unknown session`（404）。** 会话过期（闲置 30 分钟）或服务重启过。Agent 会自动重新初始化；客户端卡住不动时，删掉服务条目重新添加即可。
- **`无法启动：端口被占用`。** 端口被其他进程占用；解决办法是换一个 `core.mcp.port` 再重启，或停掉占用者。
- **连接被拒绝。** 服务没在运行，或 Agent 不在同一台机器（默认只绑回环；`0.0.0.0` 会暴露到局域网，安全全靠令牌兜底）。
- **Agent 的工具列表缺工具。** 对应分组在配置中被关了——各 `group*` 开关是排查对象，重连后列表会重建（工具列表按每次服务启动构建）。
- **`isError: not inside a loaded world`。** 状态与控制工具拒绝主菜单状态；身处已加载世界中即可。
- **日志看起来是空的。** `logCapture: mod` 只记录 NeoMacros 日志；`all` 覆盖全量游戏日志。
