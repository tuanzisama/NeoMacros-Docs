---
title: "下载与渠道"
---

NeoMacros 有四种构建渠道。渠道写在版本号里——文件名和 jar 内部一致，装了哪个版本一目了然，游戏内的更新检查也会对准自己的渠道。

## 命名规则

| 渠道 | 文件名示例（26.3 节点） | 适合谁 |
| --- | --- | --- |
| release | `neomacros-26.3-fabric-0.1.0.jar` | 所有人；打 tag 的稳定版本 |
| dev | `neomacros-26.3-fabric-0.1.0-dev.123+abc1234.jar` | 想第一时间用新功能的玩家；每次 main 分支推送都会重打 |
| canary | `neomacros-26.3-fabric-0.1.0-canary.45+def5678.jar` | 测试者；按需构建的实验版本 |
| local | `neomacros-26.3-fabric-0.1.0-local.jar` | 从源码自行编译的开发者 |

dev/canary 文件名的读法：`0.1.0` 是基线版本，`-dev.123` 是渠道加 CI 构建号（越大越新），`+abc1234` 是构建对应的提交。Minecraft 版本永远是 `neomacros-` 后面那一段——下载与游戏版本一致的文件（比如 Minecraft 26.3 就选 `26.3`）。

## 下载地址

- **release**：[发布页](https://github.com/tuanzisama/NeoMacros/releases)；选最新的非预发布版本，再挑与游戏版本一致的 jar。
- **dev**：滚动的 [`dev` 标签页](https://github.com/tuanzisama/NeoMacros/releases/tags/dev)——永远指向最新一次构建，旧产物随发布被替换。
- **canary**：滚动的 [`canary` 标签页](https://github.com/tuanzisama/NeoMacros/releases/tags/canary)，按需发布。

每次发布都附带 `SHA256SUMS` 校验文件。中国大陆访问 GitHub 时通时断；mod 的更新检查已为此做了规避（见下文），发布产物也会随站点更新清单暴露在 [neomacros.tuanzi.ink](https://neomacros.tuanzi.ink)。

## 更新检查

mod 默认只对比自己所在的渠道（dev 构建盯 dev 渠道；local 构建从不自动检查）。发现新版本时：游戏内弹出 toast 加聊天卡片，已连接的网页编辑器顶部出现横幅。全部行为可在 设置 → **更新** 中调整：

- *检查更新*——开关自动检查。
- *检查间隔*——两次检查间隔的小时数。
- *更新渠道*——`auto` 跟随当前构建渠道，也可以固定为 `release`/`dev`/`canary`。
- 按版本控制：在聊天卡片点 **忽略此版本**（或执行 `/neomacros update ignore`），用 `/neomacros update clear-ignore` 撤销；`/neomacros update check` 随时手动检查。

由于 `api.github.com` 在中国大陆基本不可达，检查器优先请求 `https://neomacros.tuanzi.ink/update/updates.json`（随文档站部署），失败才回退 GitHub API。清单里列出每个渠道的最新版本、按游戏版本区分的下载链接和 SHA-256 校验值。
