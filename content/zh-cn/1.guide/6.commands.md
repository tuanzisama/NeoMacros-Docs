# 客户端命令

脚本可以添加自己的客户端聊天命令。注册通过 `neo.command` 完成，使用声明式 spec、类型化参数槽，以及接收解析值的处理器。注册（以及以编程方式执行命令）需要 `command` 权限——参见[权限与信任](./permissions-trust)。

## 注册命令

命令 spec 包含 `name`、`description`、可选的 `args` 槽映射，以及 `handler`：

```js
const { command, chat } = neo;

export function startup() {
    command.register({
        name: 'greet',
        description: 'Greets someone, N times',
        args: {
            target: command.arg.player(),
            times: command.arg.int().defaultTo(1),
            note: command.arg.greedy().optional(),
        },
        handler(ctx) {
            const n = ctx.args.times;
            for (let i = 0; i < n; i++) {
                chat.log(`Hello, ${ctx.args.target}!`);
            }
        },
    });
}
```

把注册放进 `services` 脚本：`startup` 在激活时运行一次，正好符合命令注册所需要的形态。执行 `/neomacros reload` 和 `/neomacros trust <script>` 之后，在聊天里输入 `/greet Steve 3 nice work` 就能看到它触发。

## 构建类型化参数槽

槽通过 `command.arg` 创建，顺序与它们消耗输入的顺序一致。共有八种：

| 种类 | 消耗内容 |
| --- | --- |
| `int()` | 一个整数 |
| `float()` | 一个小数 |
| `bool()` | `true` / `false` |
| `word()` | 一个单词 |
| `string()` | 一个单词，按字符串保留 |
| `greedy()` | 剩下的全部内容 |
| `player()` | 一个玩家名风格的单词 |
| `pos()` | 一个方块坐标 |

解析按声明顺序逐个用槽去消耗原始剩余串：第一个槽拿走第一个单词，依此类推。两个修饰符可以改变槽的严格程度：

- `.optional()` —— 输入缺失时回退，而不是报错（该键保持缺席，而不是变成占位值）。
- `.defaultTo(v)` —— 输入缺失时回退为 `v`。

必填槽没有剩余输入时会报错，命令以解析错误告终。`greedy` 最好放在最后：它会吞掉整个剩余字符串，连空格一起。

## 读取处理器上下文

处理器收到一个上下文对象，带两个成员：

- `ctx.args` —— 解析后的类型化值，按槽名索引（`ctx.args.times` 是数字，因为槽是 `int()`）。
- `ctx.raw` —— 命令名之后的整个剩余字符串，原封未动。

`ctx.raw` 适合原样传递文本，或原样记录玩家输入了什么。

## 在不再需要时注销

`command.register` 返回一个不透明句柄。把它——或命令名——传给注销即可：

```js
const handle = command.register({ name: 'greet', description: '...', handler(ctx) {} });

command.unregister(handle);    // by handle
command.unregister('greet');   // or by name
```

注销本身不需要权限。对于只在某个条件成立期间存在的命令，围绕该条件进行注册和注销，而不是让命令一直存活。完整成员列表见 [command 门面](../api/modules/ui/command)页。
