title: "事件系统"
---

NeoMacros 脚本是事件驱动的：游戏不断发布世界正在发生之事的快照，由处理器决定如何处理它们。本页介绍 `neo.events` 上的订阅工具、可拦截事件的取消与改写，以及如何让高开销的事件保持廉价。

## 事件方向

每个事件都声明自己的流向，它决定了处理器能对事件做什么：

| 方向 | 含义 | 能力 |
| --- | --- | --- |
| `c2s` | 客户端即将做出动作（按键、发送聊天、方块/实体交互） | 可取消；`chat:send` 还可改写消息 |
| `s2c` | 服务器发来的内容即将落地（聊天、标题、告示牌） | 可取消；白名单字段可本地改写 |
| `local` | 客户端本地派生状态（tick、生命体征、世界、界面切换） | 仅观测，永不可取消 |

`e.direction` 在每个载荷上暴露方向字面量；载荷接口经由方向中间基类继承——运行时用 `e instanceof neo.InputEvent` 即可甄别 c2s 事件。

## events.on 订阅

`events.on(name, handler)` 注册一个异步监听器。处理器在脚本的事件循环上运行，并以冻结快照对象的形式收到载荷：

```js
const { events, chat } = neo;

const handle = events.on('player:health', (payload) => {
    chat.actionbar(`health: ${payload.health}`);
});
```

事件名遵循 `domain:name` 约定——`chat:receive`、`player:health`、`input:keyPress`、`world:sound`。裸的内置 `tick` 是唯一的例外。通配符也可用：`domain:*` 匹配整个域，`*` 匹配所有事件（`tick`、`world:sound`、`world:blockUpdate` 等高流量事件默认不参与通配符分发）。

取消订阅时把句柄传回去即可：

```js
events.off(handle);              // by handle
events.off('player:health');     // or by event name
```

模块加载期间创建的订阅归属该模块，模块卸载时自动退订。

## 清单声明的订阅

事件宏在 `config.event.on` 下声明自己关心的事件，引擎会为每次事件发生调用脚本导出的 `startup(payload)`——不需要手动接线。手动 `events.on` 订阅可以与声明的订阅共存，适用于服务脚本、通配符监听，以及生命周期由脚本掌控的订阅。声明式写法见[你的第一个脚本](./first-script)。

## 用 onSync 拦截：取消与改写

可取消事件接受通过 `events.onSync` 创建的同步订阅。回调在分发线程上运行，收到的载荷可写：直接改写白名单字段，用 `e.cancel()` 或可写的 `e.cancelled` 访问器取消。返回值会被忽略——效果经由事件对象传递。

```js
const { events } = neo;

events.onSync('chat:send', (e) => {
    if (e.message.includes('secret')) {
        e.cancel();                     // 否决这条消息
    }
    if (e.message === 'typo') {
        e.message = 'fixed';            // 改写上行文本
    }
});

events.onSync('screen:signEdit', (e) => {
    e.lines = ['signed by neo', '', '', ''];
    e.closeScreen = true;               // 跳过编辑器直接提交
});
```

同步回调必须保持简短：整个游戏都会停在原地等它们返回，回调要做的就是判断并修改——不用 `await`，不用循环。

### 优先级

多个脚本可以拦截同一事件。`options.priority` 决定链的顺序——`LOWEST` 先执行、`HIGHEST` 后执行且拥有最终决定权，`MONITOR` 仅作观测（其修改与取消会被丢弃并告警）。请传 `neo.EventPriority` 常量，不要传字符串：

```js
events.onSync('chat:title', (e) => {
    e.text = 'redirected';
}, { priority: neo.EventPriority.HIGH, ignoreCancelled: true });
```

链上靠后的处理器**能看到先前写入**并可覆盖；取消状态同样遵循 last-write-wins：靠后的处理器可用 `e.cancelled = false` 撤销先前的 `cancel()`。`options.ignoreCancelled: true` 则在事件已被取消时跳过本处理器。

## 等待单次事件

三个辅助函数覆盖了一次性模式：

- `events.once(name, handler)` 只触发一次并自动退订。
- `events.waitFor(name)` 返回以下一个载荷落定的 Promise。
- `events.waitForUntil(name, filter, timeoutMillis)` 以第一个匹配 `filter` 的载荷落定，超时后以异常拒绝。过滤器跑在分发线程上，必须保持廉价。

```js
const { events, chat } = neo;

try {
    await events.waitForUntil('player:health', (p) => p.health < 6, 30000);
    chat.actionbar('low health!');
} catch {
    chat.log('no low-health moment within 30s');
}
```

## 过滤高频率事件

`tick` 每秒触发二十次，`world:blockUpdate` 在客户端每收到一次方块状态变化时触发。处理器若在每次触发时都做实际工作，会占满脚本的循环。护栏是提前返回：

```js
const { events, chat } = neo;

let n = 0;

events.on('tick', () => {
    n += 1;
    if (n % 20 !== 0) return;        // 20 tick 里放行 1 tick
    chat.actionbar('once a second');
});
```

`tick` 载荷自带 `count`，可直接用 `payload.count` 代替本地计数器做闸门。无论用什么护栏，函数体都要尽量少做事。

## 自定义事件

脚本也可以发布事件。`events.register('myscript:burst')` 预留一个带命名空间的名字（不能占用内置域），之后 `events.emit('myscript:burst', payload)` 走异步通道投递给其他监听器。载荷键不得占用保留字 `type`、`timestamp`、`cancellable`、`direction`。

全部内置事件的字段表在 API 部分查阅：[events facade](../api/modules/core/events)、[chat:receive](../api/events/chat/chat-receive)、[player:health](../api/events/player/player-health) 以及其下的事件目录。
