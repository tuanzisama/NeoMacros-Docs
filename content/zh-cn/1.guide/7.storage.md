---
title: "存储与状态"
---

每个脚本在 `neo.storage` 上拥有一个隔离的键值存储。它保存可 JSON 序列化的值，跨 `/neomacros reload` 和完整游戏重启存活，并且按脚本隔离——别的脚本无法读写你的键。

## 值的写入和读取

四个成员覆盖整个门面：

```js
const { storage } = neo;

storage.put('joined', true);            // write
const v = storage.get('joined');        // read, or null when absent
storage.has('joined');                  // exists?
storage.remove('joined');               // delete one key
```

`storage.put(key, null)` 同样会删除键，而 `storage.get` 对从未写入过的键返回 `null`。存储按脚本的源文件为键，因此只要入口文件名不变，重命名文件夹不会丢数据。

## 能存什么

值必须是纯 JSON 数据：对象、数组、字符串、数字、布尔——以及用于删除的 `null`。类实例、Map、函数和活句柄都放不进去。保存位置时，存进的是它的字段而不是句柄：

```js
const p = player.self.pos;
storage.put('lastPos', { x: p.x, y: p.y, z: p.z });
```

试图存入不可序列化的数据是最常见的存储 bug；如果 `put` 开始抛错，参见[排错指南](./troubleshooting)。

## 设置对象模式

经典模式：默认值定义在脚本里，已保存的内容合并进来，合并后的对象再写回去，这样新的默认字段对老用户也能生效：

```js
const { storage, chat } = neo;

const DEFAULTS = { welcome: true, warnHealth: 6 };

export function startup() {
    const saved = storage.get('settings') ?? {};
    const settings = { ...DEFAULTS, ...saved };
    storage.put('settings', settings);

    if (settings.welcome) chat.log('settings loaded');
}

export function setWarning(value) {
    const saved = storage.get('settings') ?? {};
    storage.put('settings', { ...DEFAULTS, ...saved, warnHealth: value });
}
```

`storage.get('settings') ?? {}` 处理的是首次运行时什么都还没存过的情况。把默认值展开在已保存值之下，意味着保存的文件只需要写下它刻意改动的字段。

## 计数器与冷却

数字同样容易持久化。计数器随每次事件递增：

```js
const n = (storage.get('msgCount') ?? 0) + 1;
storage.put('msgCount', n);
```

冷却则比较时间戳——脚本里 `Date.now()` 完全够用：

```js
const now = Date.now();
const last = storage.get('lastPing') ?? 0;

if (now - last < 5000) return;          // 5s cooldown not elapsed
storage.put('lastPing', now);
```

写入应当留在真正重要的地方：一个每次 `tick` 都递增的计数器每秒要写二十次，纯属浪费——累积在本地变量里、定期落盘，就能避免。

## 存储还是文件

存储适合脚本自己要读回的结构化状态：设置、计数器、冷却、缓存。它不需要权限，而且对玩家不可见。当数据是给人看的——笔记、日志、想在编辑器里打开的导出——载体就该是文件，通过 `neo.fs` 写出；那条路需要 `fs` 能力以及随之而来的信任（参见[权限与信任](./permissions-trust)）。完整签名见 [storage 门面](../api/modules/core/storage)页。
