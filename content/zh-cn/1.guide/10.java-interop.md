::warning
授予 `java` 权限等于把完全的宿主访问交给脚本：JVM 上的每一个类，没有任何过滤，还能通过反射执行任意代码。这个权限只适合交给读过并且看懂了的脚本。
::

NeoMacros 把脚本挡在精心设计的门面之后，而 `neo.java` 是越过它们的逃逸层——一座通往游戏所运行宿主 JVM 的桥。当某个门面覆盖不到原版内部机制、需要某个 Java 库，或者要照着一份面向 Minecraft 自身类编写的社区配方操作时，用到的就是它。

## 按二进制名查找

`java.type` 按二进制名（点分隔）解析一个类，并返回类代理。Minecraft 类以 Mojmap 命名；映射层会在调用点做翻译，因此无论运行时 jar 是哪一个，写出的都是映射时代的名字。

```js
const { java, chat } = neo;

const UUID = java.type('java.util.UUID');
const id = UUID.randomUUID();          // statics dispatch straight off the proxy
chat.log(id.toString());               // object proxies dispatch instance methods
```

类代理把静态字段暴露为值、把静态方法暴露为可调用对象。构造实例经由代理的 `new` 成员完成：

```js
const File = java.type('java.io.File');
const f = File.new('config/neomacros');
```

每个从宿主回到脚本的宿主对象都会被包装成对象代理：成员读取会触达底层的真实字段和方法。`java.proxy(interfaces, handlers)` 则方向相反，构建一个把方法分派给脚本函数的宿主对象。

## 集合转换器

脚本数组与 Java 集合不会隐式互操作。三个转换器覆盖这个场景：

```js
java.toList(['a', 'b']);                    // script array → live java.util.List
java.fromList(someJavaCollection);          // host collection → script array
java.toArray(['a'], 'java.lang.String');    // script array → typed host array
```

## reflect 与精确签名

`java` 代理的是公开表面，而 `neo.reflect` 解析的是精确声明——私有成员和特定重载都包括在内：

```js
const { reflect } = neo;

const m = reflect.method(target, 'getSender', ['int']);   // exact overload
const v = reflect.invoke(m, target, [42]);                // omit target for statics
const obj = reflect.newInstance('java.util.ArrayList');
reflect.className(v);                                     // runtime class of any value
```

代理查找看不到的成员，就靠反射来调用。它走同一个 `java` 权限。

## raw 客户端入口

接触原版内部机制，通常的起点是客户端实例本身。`neo.client.minecraft`（需要 java 权限）把 raw 客户端以对象代理的形式暴露出来；它等价于 `java.type('net.minecraft.client.Minecraft').getInstance()`。大多数 Minecraft 类的配方从这里开始。游戏状态属于主线程，读写要包进 `thread.runOnMain`（参见[异步与线程](./async-threading)）。
