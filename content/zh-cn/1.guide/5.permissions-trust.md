---
title: "权限与信任"
---

脚本运行在沙箱里。读取世界状态、输出聊天、绘制覆盖层、调度定时器永远被允许——这是基础表面。任何越过它的东西（文件、网络、命令、宿主 JVM）都必须由脚本声明、由你授予。

## 了解哪些能力受门禁管控

| 权限 | 解锁内容 |
| --- | --- |
| `fs` | `neo.fs` 的全部成员：`readText`、`writeText`、`readJSON`、`writeJSON`、`list`、`mkdir`、`delete` 等 |
| `net` | `neo.net` 的全部成员：`fetch`、`get`、`post` |
| `command` | `neo.command.register` 和 `neo.command.execute` |
| `java` | `neo.java`、`neo.reflect` 和 `neo.client.minecraft` |

前三项是范围受限的能力：授予 `fs` 只解锁相对于游戏目录的文件访问，别无其他。`java` 权限则不同——它授予完全的宿主访问且不做任何类过滤，因此应把它当作最高级别的信任对待（参见 [Java 互操作](./java-interop)）。

## 在清单中声明能力

脚本用可选的顶层 `permissions` 字段声明自己的需求：

```yaml
# config/neomacros/macros/event/backup-notes/neomacro.yml
name: backup-notes
version: 1.0.0
author: you
description: keeps a running note file
permissions: ["fs"]

config:
  event:
    on: [chat:receive]
```

没有 `permissions` 列表（或列表为空）的脚本完全运行在基础表面上，永远不会触发授权提示。未知的能力名会被信任门禁拒绝——拼写错误会直接失败（fail closed），而不是悄悄扩大访问范围。

## 给脚本授予信任

首次加载一个声明了能力的脚本时，聊天提示会列出它请求的内容。在你做出决定之前，脚本运行在"一律拒绝"的视图下——受门禁的调用会抛错。点击提示（它会替你执行命令），或者自己输入：

```text
/neomacros trust backup-notes
```

信任决定以脚本的内容哈希为键，这带来两个结果：

- 编辑文件会改变哈希，因此已信任的脚本绝不可能悄悄长出新能力——提示会重新出现，你审阅改动后再次批准即可。
- 决定跨重启持久保存（存放在 `config.json` 里）。

改动后重新批准是正常工作流；把提示当作审阅步骤即可。

## 了解不受信任的脚本做不了什么

没有对应授予时，脚本：

- 无法通过 `neo.fs` 读写任何文件；
- 无法通过 `neo.net` 发起任何网络请求；
- 无法注册或执行客户端命令；
- 无法触碰 `neo.java`、`neo.reflect` 或 `neo.client.minecraft`。

基础表面的一切仍然可用：事件、定时器、聊天输出、世界与玩家读取、HUD 与渲染覆盖层，以及它自己的 `neo.storage` 存储。受门禁的调用在触发时抛错，错误会显示在 `/neomacros errors` 里——参见[排错指南](./troubleshooting)。

## 遵循最小权限原则

只授予脚本真正用到的能力，优先选择声明更少的脚本。信任一个不是你写的脚本之前，先读它的清单——`permissions` 一行会准确告诉你该在代码里找什么。索要 `java` 的脚本值得通读一遍；什么都不索要的脚本可以直接运行。
