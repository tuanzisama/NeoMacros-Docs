---
title: "从 JsMacros 迁移"
---

NeoMacros 与 JsMacros 说的是同一门语言——都是跑在 JS 引擎上的普通 ES
模块——但周边的 API 是全新的：用 `neo.*` 门面代替 JsMacros 全局、用驼峰式
`domain:name` 事件名代替 `UPPER_SNAKE`、I/O 异步优先、脚本按清单文件组织。
如果你手上有一批 JsMacros 1.x 脚本，有两条路可走，而且可以随意混用：

- **用兼容层，今天就能跑。** jsmacros-compat 在 `neo.*` 之上重建了
  JsMacros 1.9.2 风格的脚本 API。`Player.getPlayer()`、
  `JsMacros.on('Tick', ...)` 这类代码几乎不用改就能继续运行。
- **按原生 API 重写**（见[走向原生](#走向原生)），这是长期正道。兼容层让
  这一步可以渐进：一次只搬一个脚本，只搬值得搬的部分。

## 安装兼容层

1. [下载兼容层压缩包](https://neomacros.tuanzi.ink/downloads/jsmacros-compat.zip)（约 105 KB）并解压，
   得到一个 `jsmacros-compat` 文件夹。
2. 把这个文件夹复制进脚本根目录 `config/neomacros/macros/`。
3. 在每个使用旧 API 的脚本开头 import 一次：

```js
import './jsmacros-compat/src/index.js';
```

导入即自动挂载完整的 JsMacros 全局表面——`JsMacros`、`Player`、`World`、
`Chat`、`Client`、`Time`、`KeyBind`、`Hud`、`FS`、`GlobalVars`、`Request`、
`Reflection`、`JavaUtils`、`JavaWrapper`、`PositionCommon`、`Utils`、
`Color`——挂载是幂等的，多个脚本同时导入也不会重复安装。

::note
兼容层是纯脚本级库：不分发任何 Java 代码，完全活在你的脚本文件夹里，删掉
文件夹即卸载。
::

编辑器与 `tsc` 支持：把 `jsmacros-compat/types/jsmacros-compat.d.ts`
加进你的 `tsconfig`。

## 注意脚本目录结构

兼容层桥接的是 API 表面，不是宿主模型。JsMacros 会执行丢进脚本文件夹的
每一个 `.js` 文件；NeoMacros 则是**一个脚本一个文件夹**，每个文件夹带一份
`neomacro.yml` 清单，按触发方式放进 `keypress/`、`event/` 或 `services/`
（见[目录布局](../guide/getting-started)）。实际对应关系：

- 在顶层调用 `JsMacros.on(...)` 并一直运行到游戏关闭的 JsMacros 脚本 →
  放进 `services/`。服务只启动一次并自行保活，旧的自注册风格经兼容层照常工作。
- 只应在声明的游戏事件到来时唤醒的脚本 → 改造成在 `config.event.on` 中
  声明事件的 `event` 宏（见[第一个脚本](../guide/first-script)），脚本主体
  什么时候方便什么时候搬。
- 按键脚本 → 放进 `keypress/` 并配 `key_code`，或者继续用兼容层的
  `KeyBind` 表面。

## 开箱即用的部分

- **读取面**（同步、活句柄）：玩家/世界/实体/方块查询、
  `Chat.log/say/actionbar`、`Time.time()`、经 `KeyBind` 的按键注入、
  `GlobalVars`（底层走 `storage`）、实体帮助类 4 层主链 + 75 个专门化壳、
  背包面 + 16 个专门化背包壳、`Color`、`PositionCommon`、`Utils` 的 base64。
- **事件桥接**：`JsMacros.on/once/off/waitForEvent`，回调 `(event, context)`
  形态，36 个已桥接事件名（含旧 `UPPER_SNAKE` 别名），逐事件 payload 适配器，
  自定义事件，JS 侧 filterer。
- **渲染**：`Hud.createDraw2D`（文本元素）与 `Hud.createDraw3D`
  （线框盒/线/点），保留 JsMacros 的 register 生命周期。
- **逃逸层**：`Reflection`、`JavaUtils`、`Client.getMinecraft`——与
  JsMacros 一样受 NeoMacros 的 java 权限门控。

## 这些地方要补 await

NeoMacros 异步优先。以下 JsMacros 同步面保留签名但返回 Promise——请补
`await`：

| JsMacros 调用 | 兼容层返回 |
| --- | --- |
| `FS.*`（全部文件操作） | `Promise<...>` |
| `Request.get/post/create(url).get()` | `Promise<ResponseCompat>`（其 `text()/json()/byteArray()` 异步） |
| `Time.sleep(ms)` | `Promise<void>` |
| `Client.waitTick([n])`、`Client.runOnMainThread(fn, true)` | `Promise<void>` / `Promise<unknown>` |
| `Inventory.click/dropSlot/quick/swapHotbar/split/grabAll/closeAndDrop/close` | `Promise<void>` |
| `ClientPlayer.dropHeldItem`、交互管理器动作 | `Promise<void>` |

::warning
不 await 的 `FS.exists(p)` 写在 `if` 里恒为真——分支判断的是 Promise 对象
而不是文件。请逐个迁移调用点，别批量替换。
::

## 不可用的部分

所有在 NeoMacros 中没有对应实现的 JsMacros 成员都**保留原方法名、调用时抛
`UnimplementedError`**——绝不静默缺失，脚本要么正常工作，要么在确切的调用点
大声失败。重点：

| 缺失区域 | 说明 |
| --- | --- |
| 包访问 | `RecvPacket`/`SendPacket` 事件及一切包级工具——NeoMacros 不暴露包层 |
| `Title` / `SignEdit` 事件 | NeoMacros 没有标题、告示牌编辑事件（只有本地 `chat.actionbar` 输出） |
| 背包点击事件 | `ClickSlot` 事件族——NeoMacros 不暴露背包事件 |
| 屏幕与纹理 | 创建或控制屏幕（`ScriptScreen`、`FHud.createScreen/openScreen`） |
| 运行时 Java 编译 | 在运行时编译 Java 源码 |
| 专门化实体状态 | 75 个实体壳中 NeoMacros 未暴露读取的部分仍是抛错桩 |

完整清单——类级 1,157 项、事件对象级 24 项、19 个不支持的事件名，每一项都
注明原因——见[兼容层压缩包](https://neomacros.tuanzi.ink/downloads/jsmacros-compat.zip)内的
`docs/missing-apis.md`。

## 值得知道的行为差异

以下行为不抛错——只是与 JsMacros 不同：

| 差异点 | 变化 |
| --- | --- |
| FS 路径根 | 路径相对游戏目录解析，而不是脚本文件夹 |
| 实体读取是活句柄 | 帮助类经活句柄实时重读，不在创建时快照；已消失的实体读到 `null`/`undefined` |
| 显示名 | `getName`/`getDefaultName` 由 id 推导（`minecraft:deepslate_bricks` → `Deepslate Bricks`），无翻译表查询 |
| `isDay` / `isNight` | 固定原版时间窗：夜晚为第 13000–23000 刻 |
| 消息改写 | `RecvMessage.text` / `SendMessage.message`：读取可用，赋值抛错——NeoMacros 只支持取消，不支持改写 |
| 自定义事件 | 不可取消 |
| `ANYTHING` 通配 | 默认跳过高频事件（`tick`、`world:sound`、`world:blockUpdate`） |
| `HeldItemChange.offHand` | 恒为 `false`——持物品切换事件只对主手触发 |
| 带样式文本 | `Chat.log` 的带样式文本经旧式 `§` 代码渲染；悬停/点击样式被丢弃 |
| 世界扫描 | `iterateSphere`/`iterateBox` 是纯 JS 循环——大体积场景下远慢于原生扫描器 |

行为近似与签名偏差的完整清单（`docs/missing-apis.md` 第 8 节）随
[兼容层压缩包](https://neomacros.tuanzi.ink/downloads/jsmacros-compat.zip)一并分发。

## 走向原生

当某个脚本准备告别兼容层时，映射基本是机械的：

| JsMacros | NeoMacros | 说明 |
| --- | --- | --- |
| `JsMacros.on/once/off/waitForEvent` | `events.on/once/off/waitFor` | `UPPER_SNAKE` 事件名变为驼峰式 `domain:name`；六个可取消事件必须用 `events.onSync` |
| `Chat` | `chat` | 另有 `title`/`toast` |
| `Player` | `player` | |
| `World` | `world` | |
| `Client` | `client` | |
| `KeyBind` | `input` | |
| `Hud`（Draw2D/Draw3D） | `hud` + `render` | |
| `FS` | `fs` | 原生即异步——每次调用都要 `await` |
| `GlobalVars` | `storage` | |
| `Request` | `net` | |
| `Reflection` / `JavaUtils` / `JavaWrapper` | `java` + `reflect` | 受 java 权限门控 |
| `Time.sleep(ms)` | `thread.sleep(ms)` | 兼容层的 `Time.time()` 本来就是 `Date.now()` |
| `PositionCommon` | `Pos3D` 等 | |
| `Color` | 普通 ARGB 整数 | 兼容层今天提供的助手函数就是这套 |

随迁移而来的还有两处形态变化：事件回调收到的是单个 payload 对象，而不是
`(event, context)` 两个参数；脚本加载期间创建的订阅会被自动追踪，脚本卸载时
自动退订——常见场景无需手动清理。
