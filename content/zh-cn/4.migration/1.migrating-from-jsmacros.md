---
title: "从 JsMacros 迁移"
---

JsMacros 与 NeoMacros 的脚本共享同一门语言——普通 ES 模块——但不共享
API：`neo.*` 门面代替 JsMacros 全局，驼峰式 `domain:name` 事件名代替
`UPPER_SNAKE`，I/O 异步优先，每个脚本是一个带清单文件的文件夹。两条迁移
路径，可随意混用：

- **兼容层** —— [jsmacros-compat](#兼容层安装)在 `neo.*` 之上重建
  JsMacros 1.9.2 风格的脚本 API；`Player.getPlayer()`、
  `JsMacros.on('Tick', ...)` 以极小改动继续运行。
- **按原生 API 重写**（见[原生 API 对照](#原生-api-对照)）——长期路径；
  兼容层使其可以渐进，一次一个脚本或一个部分。

## 兼容层安装

1. [兼容层压缩包](https://neomacros.tuanzi.ink/downloads/jsmacros-compat.zip)
   （约 105 KB）解压为一个 `jsmacros-compat` 文件夹。
2. 文件夹放进脚本根目录 `config/NeoMacros/macros/`。数据目录名取模组显示名；
   改名前的 `config/neomacros` 旧安装不会被迁移。
3. 每个使用旧 API 的脚本在开头 import 一次：

```js
import './jsmacros-compat/src/index.js';
```

导入即挂载完整的 JsMacros 全局表面——`JsMacros`、`Player`、`World`、
`Chat`、`Client`、`Time`、`KeyBind`、`Hud`、`FS`、`GlobalVars`、`Request`、
`Reflection`、`JavaUtils`、`JavaWrapper`、`PositionCommon`、`Utils`、
`Color`——挂载幂等：多脚本并行导入也只安装一次。

::note
兼容层是纯脚本级库：无 Java 代码，无脚本文件夹之外的文件；卸载即删除
文件夹。
::

编辑器与 `tsc` 支持：`jsmacros-compat/types/jsmacros-compat.d.ts` 加入
`tsconfig`。

## 脚本目录结构

兼容层桥接的是 API 表面，不是宿主模型。JsMacros 执行脚本文件夹里的每个
`.js` 文件；NeoMacros 一个脚本加载一个文件夹，各带一份 `neomacro.yml`
清单，置于触发类型目录之下——`keypress/`、`event/` 或 `services/`
（见[目录布局](../guide/getting-started)）。对应关系：

- 顶层调用 `JsMacros.on(...)`、生命周期为整个游戏会话的脚本 →
  `services/`；自注册风格经兼容层照常工作。
- 只在声明事件到来时唤醒的脚本 → `event` 宏，在 `config.event.on` 中声明
  （见[第一个脚本](../guide/first-script)）；脚本主体择机搬移。
- 按键脚本 → `keypress/` 加 `key_code`，或兼容层的 `KeyBind` 表面。

## 覆盖范围

- **读取面**（同步、活句柄）：玩家/世界/实体/方块查询、
  `Chat.log/say/actionbar`、`Time.time()`、经 `KeyBind` 的按键注入、
  `GlobalVars`（底层 `storage`）、实体帮助类 4 层主链 + 75 个专门化壳、
  背包面 + 16 个专门化背包壳、`Color`、`PositionCommon`、`Utils` 的
  base64。
- **事件桥接**：`JsMacros.on/once/off/waitForEvent`，回调 `(event, context)`
  形态，36 个已桥接事件名（含旧 `UPPER_SNAKE` 别名），逐事件 payload
  适配器，自定义事件，JS 侧 filterer。
- **渲染**：`Hud.createDraw2D`（文本元素）、`Hud.createDraw3D`
  （线框盒/线/点），含 JsMacros register 生命周期。
- **逃逸层**：`Reflection`、`JavaUtils`、`Client.getMinecraft`——位于
  NeoMacros 的 java 权限之后，与 JsMacros 中的等价物一致。

## 异步调用面

NeoMacros 异步优先。以下表面保留 JsMacros 签名、返回 Promise：

| JsMacros 调用 | 兼容层返回 |
| --- | --- |
| `FS.*`（全部文件操作） | `Promise<...>` |
| `Request.get/post/create(url).get()` | `Promise<ResponseCompat>`（其 `text()/json()/byteArray()` 异步） |
| `Time.sleep(ms)` | `Promise<void>` |
| `Client.waitTick([n])`、`Client.runOnMainThread(fn, true)` | `Promise<void>` / `Promise<unknown>` |
| `Inventory.click/dropSlot/quick/swapHotbar/split/grabAll/closeAndDrop/close` | `Promise<void>` |
| `ClientPlayer.dropHeldItem`、交互管理器动作 | `Promise<void>` |

::warning
不 await 的 `FS.exists(p)` 写在 `if` 里恒为真——分支判断的是 Promise 对象
而不是文件。调用点逐个迁移，不做批量替换。
::

## 缺失面

无 NeoMacros 对应实现的成员**保留原方法名、调用时抛
`UnimplementedError`**——无静默缺失，失败落在确切调用点。重点：

| 缺失区域 | 说明 |
| --- | --- |
| 包访问 | JsMacros 事件名无桥接；原生 `packet:receive`/`packet:send` 事件、事件作用域 `PacketBuffer` 句柄与 `client.createPacketBuffer`/`sendPacket`/`packetIds` 面承载同一表面，供直接使用 |
| `Title` / `SignEdit` 事件 | JsMacros 事件名无桥接；原生 `chat:title`、`chat:actionbar`、`screen:signEdit` 事件承载同一表面，供直接 `events` 订阅 |
| 背包点击事件 | `ClickSlot` 事件族——无背包事件 |
| 自定义屏幕与纹理 | JsMacros `ScriptScreen`/`FHud.createScreen` 壳仍是抛错桩；原生 `player.buildScreen` 会话、屏幕 builder 族与 `hud.texture` 注册表承载创建，供直接使用 |
| 运行时 Java 编译 | 运行时编译 Java 源码 |
| 专门化实体状态 | 原生物种状态树已完整；兼容层壳早于它，桥接之外的读取仍是抛错桩 |

完整清单——类级 1,157 项、事件对象级 24 项、19 个不支持的事件名，每项
注明原因——见[兼容层压缩包](https://neomacros.tuanzi.ink/downloads/jsmacros-compat.zip)
内的 `docs/missing-apis.md`。

## 行为偏差

以下不抛错——行为与 JsMacros 不同：

| 差异点 | 变化 |
| --- | --- |
| FS 路径根 | 路径相对游戏目录解析，而非脚本文件夹 |
| 实体读取是活句柄 | 帮助类经活句柄实时重读，不在创建时快照；已消失的实体读到 `null`/`undefined` |
| 显示名 | `getName`/`getDefaultName` 由 id 推导（`minecraft:deepslate_bricks` → `Deepslate Bricks`），无翻译表查询 |
| `isDay` / `isNight` | 固定原版时间窗：夜晚为第 13000–23000 刻 |
| 消息改写 | 兼容层 `RecvMessage.text` / `SendMessage.message`：可读，赋值抛错——兼容桥无写面；原生 `events.onSync('chat:send')` 直接改写 `e.message` |
| 自定义事件 | 不可取消 |
| `ANYTHING` 通配 | 默认跳过高频事件（`tick`、`world:sound`、`world:blockUpdate`） |
| `HeldItemChange.offHand` | 恒为 `false`——持物品切换事件仅主手触发 |
| 带样式文本 | `Chat.log` 的带样式文本经旧式 `§` 代码渲染；悬停/点击样式丢弃 |
| 世界扫描 | 兼容层 `iterateSphere`/`iterateBox` 是纯 JS 循环；原生 `world.scanBlocks`/`entity.inRadius`/`entity.inBox` 按每刻分片以 Promise 运行过滤扫描 |

完整清单：[兼容层压缩包](https://neomacros.tuanzi.ink/downloads/jsmacros-compat.zip)
内 `docs/missing-apis.md` 第 8 节。

## 原生 API 对照

脚本对兼容层的退役，大体是一张机械映射表：

| JsMacros | NeoMacros | 说明 |
| --- | --- | --- |
| `JsMacros.on/once/off/waitForEvent` | `events.on/once/off/waitFor` | `UPPER_SNAKE` 事件名变驼峰式 `domain:name`（`key:press` 现为 `input:keyPress`）；取消与改写走 `events.onSync`——可变载荷、`e.cancel()`、`neo.EventPriority` 排序 |
| `Chat` | `chat` | 另有 `title`/`toast` |
| `Player` | `player` | 经 `player.screen` 的类型化当前屏幕快照 |
| `World` | `world` | |
| `Client` | `client` | |
| `KeyBind` | `input` | |
| `Inventory` | `player.inventory` | `items` 为按槽位键控的 `Record<number, ItemStack>` |
| `Hud`（Draw2D/Draw3D） | `hud` + `render` | Draw2D/Draw3D 组件族与 `hud.texture` 注册表 |
| `FS` | `fs` | 原生即异步——每次调用 `await` |
| `GlobalVars` | `storage` | |
| `Request` | `net` | |
| `Reflection` / `JavaUtils` / `JavaWrapper` | `java` + `reflect` | 位于 java 权限之后 |
| `Time.sleep(ms)` | `thread.sleep(ms)` | `Time.time()` 即 `Date.now()` |
| `PositionCommon` | `Pos3D` 等 | |
| `Color` | 普通 ARGB 整数 | 兼容层即同一套助手函数 |

三处形态变化：事件回调接收单个 payload 对象（无 `(event, context)` 参数
对）；异步载荷为冻结快照，改写位于 `events.onSync`；模块加载期间创建的
订阅被自动追踪，模块卸载时自动移除。
