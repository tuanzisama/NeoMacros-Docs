# 事件系统

NeoMacros 脚本是事件驱动的：游戏不断发布世界正在发生之事的快照，由你的处理器决定如何处理它们。本页介绍 `neo.events` 上的订阅工具，以及如何让高开销的事件保持廉价。

## 用 events.on 订阅

`events.on(name, handler)` 注册一个异步监听器。处理器在你的脚本事件循环上运行，并以普通对象的形式收到载荷：

```js
const { events, chat } = neo;

const handle = events.on('player:health', (payload) => {
    chat.actionbar(`health: ${payload.health}`);
});
```

事件名遵循 `domain:name` 约定——`chat:receive`、`player:health`、`key:press`、`world:sound`。裸的内置 `tick` 是唯一的例外。通配符也可用：`domain:*` 匹配整个域，`*` 匹配所有事件（`tick`、`world:sound`、`world:blockUpdate` 等高流量事件默认不参与通配符分发）。

取消订阅时把句柄传回去即可：

```js
events.off(handle);              // by handle
events.off('player:health');     // or by event name
```

模块加载期间创建的订阅归属该模块，模块卸载时自动退订。

## 让清单替你订阅

事件宏在 `config.event.on` 下声明自己关心的事件，引擎会为每次事件发生调用你导出的 `startup(payload)`——不需要手动接线。手动 `events.on` 订阅可以与声明的订阅共存，适用于服务脚本、通配符监听，以及生命周期由你掌控的订阅。声明式写法见[你的第一个脚本](./first-script)。

## 用 onSync 取消事件

少数事件是可取消的——`key:press`、`chat:send`、`player:attackBlock`、`player:attackEntity`、`player:interactBlock` 和 `player:interactEntity`。只有这些事件接受同步订阅，通过 `events.onSync` 创建。回调在分发线程上运行，作用相当于一票否决：返回真值即取消事件，返回假值则放行。

```js
const { events } = neo;

events.onSync('chat:send', (payload) => {
    return payload.message.includes('secret');   // truthy vetoes the send
});
```

同步回调必须保持简短：整个游戏都会停在原地等它们返回。果断判断、立刻返回——不要 `await`，不要循环。

## 等待单次事件

三个辅助函数覆盖了一次性模式：

- `events.once(name, handler)` 只触发一次，然后自动退订。
- `events.waitFor(name)` 返回一个 promise，以下一次载荷结算。
- `events.waitForUntil(name, filter, timeoutMillis)` 用第一个匹配 `filter` 的载荷兑现，超过时限则拒绝。过滤器在分发线程上运行，请保持轻量。

```js
const { events, chat } = neo;

try {
    await events.waitForUntil('player:health', (p) => p.health < 6, 30000);
    chat.actionbar('low health!');
} catch {
    chat.log('no low-health moment within 30s');
}
```

## 过滤高频事件

像 `tick` 这样的事件每秒触发二十次，`world:blockUpdate` 则在客户端收到的每一次方块状态变化时触发。一个每次触发都干重活的处理器会霸占你脚本的循环。用提前返回做防护：

```js
const { events, chat } = neo;

let n = 0;

events.on('tick', () => {
    n += 1;
    if (n % 20 !== 0) return;        // bail out on 19 of every 20 ticks
    chat.actionbar('once a second');
});
```

`tick` 的载荷携带 tick `count`，因此也可以改用 `payload.count` 做门控。无论用哪种防护，回调体都应尽量少做事。

## 发布自己的事件

脚本同样可以发布事件。`events.register('myscript:burst')` 保留一个带命名空间的名字（不能遮蔽内置域），之后 `events.emit('myscript:burst', payload)` 会通过异步通道分发给其他监听者。载荷的字段名要避开保留字 `type`、`timestamp` 和 `cancellable`。

所有内置事件的载荷字段表都在 API 里：[events 门面](../api/events)、[chat:receive](../api/events/chat/chat-receive)、[player:health](../api/events/player/player-health)，以及其下的其余事件目录。
