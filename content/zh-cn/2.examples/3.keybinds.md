---
title: "按键切换助手"
---

同一个助手——一个替你按住原版跳跃输入的游泳辅助——用两种方式绑定到按键。
方案 A 是*按键宏*：绑定关系在清单中声明。方案 B 是*服务*：通过
[input.registerKeybind](../api/modules/input/input) 在代码里注册绑定。两者都会出现在
原版按键控制菜单的 NeoMacros 分类下，也都把切换状态保存在模块作用域中。

## 它做什么

- 按一次 V：脚本向原版 `key.jump` 绑定注入一个按住状态——在水中你会
  持续上浮、爬梯子时不必连按。动作条会确认当前状态。
- 再按一次 V：注入状态释放。
- 无论哪种情况，卸载（离开世界、`/neomacros reload`）都不会把按键
  卡在按下状态。

::warning
两种方案只装一个，不要都装——两个脚本争抢 `key.jump` 会互相打乱对方的
状态。按脚本的需要选择其中一种写法。
::

## 方案 A——按键宏（清单声明）

```text
config/neomacros/
└── macros/
    └── keypress/
        └── swim-assist/
            ├── neomacro.yml
            └── index.js
```

`neomacro.yml`：

```yaml
name: swim-assist
version: 1.0.0
author: you
description: Press V to hold jump while swimming
config:
  keypress:
    on: keypress
    default-key: key.keyboard.v
    # modifiers: [ctrl]   # require Ctrl+V instead
```

`index.js`：

```js
// Press V to hold the vanilla jump bind; press again to release.
const { input, chat } = neo;

const JUMP_BIND = "key.jump";
const ON_MSG = "Swim assist ON - press V again to release";
const OFF_MSG = "Swim assist OFF";

let enabled = false;

export function startup(event) {
    if (event.event !== "keypress") return; // only the press edge
    toggle();
}

function toggle() {
    enabled = !enabled;
    input.set(JUMP_BIND, enabled);
    chat.actionbar(enabled ? ON_MSG : OFF_MSG);
}

export function dispose() {
    if (enabled) {
        input.set(JUMP_BIND, false);
        enabled = false;
    }
}
```

## 方案 B——服务（代码注册按键）

```text
config/neomacros/
└── macros/
    └── services/
        └── swim-assist-service/
            ├── neomacro.yml
            └── index.js
```

`neomacro.yml`：

```yaml
name: swim-assist-service
version: 1.0.0
author: you
description: Swim assist with the keybind registered from code
config:
  service:
    lifecycle: world
    autostart: true
```

`index.js`：

```js
// Same helper; the keybind is registered from code at startup.
const { input, chat } = neo;

const BIND_KEY = "key.keyboard.v";
const JUMP_BIND = "key.jump";
const ON_MSG = "Swim assist ON - press V again to release";
const OFF_MSG = "Swim assist OFF";

let enabled = false;
let binding = null;

export function startup() {
    binding = input.registerKeybind(BIND_KEY, () => {
        enabled = !enabled;
        input.set(JUMP_BIND, enabled);
        chat.actionbar(enabled ? ON_MSG : OFF_MSG);
    });
    chat.log(`Swim assist loaded - press ${BIND_KEY} to toggle.`);
}

export function dispose() {
    if (enabled) {
        input.set(JUMP_BIND, false);
        enabled = false;
    }
    if (binding) {
        input.unregister(binding);
        binding = null;
    }
}
```

## 工作原理

**方案 A：清单负责接线。** `config.keypress` 声明触发沿
（`on: keypress`——另外两个取值是 `keydown` 与 `keyup`）和建议的初始绑定
（`default-key`）。`default-key` 只是建议值：真正的绑定和普通按键映射
一样存放在原版按键控制菜单中，玩家可以在那里改键。每次触发都会以
`{ event, key, code, clicks, modifiers }` 调用 `startup(event)`——
`event.event` 是触发沿名称，开头的守卫确保 `keydown`/`keyup` 触发
绝不会误触切换。

**方案 B：代码负责接线。** `input.registerKeybind(keyName, sink)` 接收
原版按键名和回调，返回订阅句柄。绑定在服务启动时创建——这也意味着
你可以动态计算按键（例如按配置使用不同按键），而不必把它固定在清单里。

**注入。** `input.set(bindName, down)` 按名称注入原版按键*绑定*的状态
（`key.jump`、`key.use`、`key.sprint` 等）——效果如同玩家正按着它。
这正是这里出现的两个 `input` 家族的区别：`registerKeybind`/`unregister`
管理*你自己的*绑定；`set`/`press`/`release`/`hold` 驱动*游戏的*输入。

**状态与清理。** `enabled` 位于模块作用域——顶层代码每次加载执行一次，
每次触发（或按键回调）改的都是同一个变量。`dispose()` 导出负责释放注入
的绑定，方案 B 中还会注销注册的按键。没有它，启用状态下重载会让
`key.jump` 永远卡在按住状态。

::note
`registerKeybind` 的回调在按住期间会重复触发（原版连点语义）。按住 V
一秒钟，切换会连续翻转多次——请以点按方式使用。按键宏方案实际行为
相同，所以两种方案都适合离散点按。
::

## 运行

1. 选择一个方案，在对应目录下创建文件夹（方案 A 在 `macros/keypress/`，
   方案 B 在 `macros/services/`）。
2. 执行 `/neomacros reload` 并进入世界。
3. 跳进水里，点按 V，然后松开所有按键——你会持续上浮。再点一次 V
   释放。
4. 打开 选项 → 按键控制 → 按键绑定，滚动到 NeoMacros 分类：绑定已列出，
   可以改键。

## 尝试扩展

- 双击切换：方案 A 的载荷带有 `clicks`——要求 `event.clicks >= 2`
  才切换，防止误按。
- 换一个注入的绑定：把 `key.jump` 换成 `key.sprint` 做成永久疾跑开关，
  或者用 `player.self.inWater` 加门槛，只在游泳时生效。
- 用 HUD 显示状态：把动作条一行换成 [hud.addText](../api/modules/ui/hud) 持久
  文本项，仅在启用时显示。
