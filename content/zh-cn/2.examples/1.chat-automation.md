---
title: "聊天自动化：自动问候与关键词应答"
---

一个事件宏，每次进入世界问候一次，并对聊天关键词做限速应答——
这是事件驱动脚本的标准形态：事件在清单中声明、按载荷分发、状态保存在
模块作用域里。

## 它做什么

- 收到 [world:join](../api/events/world/world-join) 时，在本地打印一条
  问候（每次会话仅一次，用模块级标志位保证）。
- 收到 [chat:receive](../api/events/chat/chat-receive) 时，监听短语
  "hello bot"（不区分大小写）并在聊天中回复——最多每 15 秒一次，
  且绝不回复自己的消息。

## 脚本

```text
config/neomacros/
└── macros/
    └── event/
        └── chat-bot/
            ├── neomacro.yml
            └── index.js
```

`neomacro.yml`：

```yaml
name: chat-bot
version: 1.0.0
author: you
description: Greets you once per session and answers a keyword
config:
  event:
    on:
      - world:join
      - chat:receive
```

`index.js`：

```js
// Greets you once per world session and answers "hello bot" in chat.
const { chat } = neo;

const GREETING = "chat-bot is at your service. Say 'hello bot' and I answer.";
const REPLY = "hi! I'm chat-bot, a script running on NeoMacros.";
const KEYWORD = /hello bot/i;
const REPLY_COOLDOWN_MS = 15000;

let greeted = false;
let lastReplyAt = 0;

// Called once per declared event, with that event's payload.
export function startup(payload) {
    if (payload.type === "world:join") {
        greetOnce();
    } else if (payload.type === "chat:receive") {
        respond(payload.message);
    }
}

function greetOnce() {
    if (greeted) return;
    greeted = true;
    chat.log(GREETING);
    chat.actionbar("chat-bot ready");
}

function respond(component) {
    const text = plainText(component);
    if (!KEYWORD.test(text)) return;
    if (text === REPLY) return; // our own reply echoes back as chat:receive
    const now = Date.now();
    if (now - lastReplyAt < REPLY_COOLDOWN_MS) return;
    lastReplyAt = now;
    chat.say(REPLY);
}

// ChatComponent arrives as plain data: a text node with nested children.
function plainText(component) {
    if (!component || typeof component.text !== "string") return "";
    let text = component.text;
    const children = Array.isArray(component.children) ? component.children : [];
    for (const child of children) {
        text += plainText(child);
    }
    return text;
}
```

## 工作原理

**一次声明，多个事件。** 清单在 `config.event.on` 里声明了两个事件，
因此每当其中任何一个触发，`startup(payload)` 都会被调用一次。由于两种
载荷结构不同，脚本按 `payload.type` 分支——每个事件载荷都带有保留字段
[`type`](../api/modules/core/events)，其值就是事件名（`"world:join"`、
`"chat:receive"` 等）。这是多事件宏的标准写法；逻辑若更适合拆开，
也可以直接分成两个文件夹。

**会话守卫。** 顶层代码只在加载时执行一次，所以每次加载时 `greeted`
都从 `false` 开始。事件宏位于 `macros/event/`，默认具有 `world`
生命周期：模组在世界会话打开时加载它们——*先于* `world:join` 发布——
并在会话关闭时卸载。因此这个标志位的确切含义就是"每次会话一次"，
下次进入世界或执行 `/neomacros reload` 后会复位。

**读取消息。** `chat:receive` 以 `ChatComponent` 承载消息——它是纯数据：
一个带 `text` 字段的文本节点，外加由嵌套节点组成的 `children` 数组。
`plainText` 以防御性方式遍历这棵树（根节点文本加上所有后代），拼成一个
字符串，供关键词匹配和回声检测使用。

**两种"静默"。** [chat.log](../api/modules/ui/chat) 只渲染在本地聊天 HUD 中，
`chat.actionbar` 只在快捷栏上方显示一条临时信息——两者都不会发到服务器，
问候语因此采用它们。关键词应答才是真正的自动化，所以它使用 `chat.say`，
并用两道守卫作为代价：自我回声检测（脚本自己发出的消息会经 `chat:receive`
回传）和 15 秒冷却。

## 运行

1. 上述文件夹位于 `.minecraft/config/neomacros/macros/event/` 下。
2. `/neomacros reload` 加载脚本，`/neomacros list` 可确认 `chat-bot`
   已加载。
3. 进入任意世界后，问候语本地显示。聊天中出现 `hello bot` 时脚本回复；
   紧接着再发一次，则会被冷却拦下。

::note
这个宏不需要 trust：`chat` 不在能力门禁之内。只有 `fs`、`net`、`java`
和 `command` 调用才会请求 [/neomacros trust](../guide/permissions-trust)。
::

## 扩展方向

- 回复中带上玩家名：服务器消息通常以 `<名字> ` 开头——切掉这个前缀，
  就能在回复里称呼对方。
- 更多关键词：单个 `KEYWORD` 正则换成一组 `{ pattern, reply }`，
  取第一个匹配项应答。
- 按维度开关：在 `respond` 里读取 [world.dimension](../api/modules/world/world)，
  应答限制在 `minecraft:overworld` 中。
