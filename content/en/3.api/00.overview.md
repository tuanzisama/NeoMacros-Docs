## Classes & types

Script-visible types handed to your code — live handles that read current
state, and immutable plain data. See the
[Classes index](./classes/entity) starting from
[`Entity`](./classes/entity), [`Player`](./classes/player),
[`ItemStack`](./classes/itemstack), [`Pos3D`](./classes/pos3d), or browse
any facade page: its signatures link to the types it uses.

Every event name maps to a payload class in the generated TypeScript
definitions, and the subscription methods resolve payload types per event
name. Payload classes share this group with the handles; start browsing
from [`BaseEvent`](./classes/baseevent).

## Events

57 client events across ten domains — [chat](./events/chat/chat-receive),
[player](./events/player/player-health), [entity](./events/entity/entity-load),
[world](./events/world/world-time), [input](./events/input/input-keyPress),
[screen](./events/screen/screen-open), [tick](./events/tick/tick), and
[game](./events/game/game-start) lifecycle. Each event page lists its
direction, payload fields, and links to the payload class it dispatches.

Events carry a traffic direction: `c2s` events intercept an upstream action
(key press, chat send, interactions), `s2c` events intercept incoming display
content before it lands (chat, titles, sign editor), and `local` events are
client-derived observations. Cancellable events accept synchronous
subscriptions via `events.onSync` with a writable payload — rewrite
whitelisted fields, cancel with `e.cancel()`, order the chain with
`neo.EventPriority` priorities (`LOWEST` first, `HIGHEST` last with the final
say, `MONITOR` observation-only). See the
[events guide](../guide/events) for the full model.

## 0.5.0: event system redesign

0.5.0 reshapes the event system around Bukkit-style mutable events:

| Old (<0.5.0) | New (0.5.0+) |
| --- | --- |
| `onSync(name, e => e.key === 'x')` (truthy-return cancel) | `onSync(name, e => { if (...) e.cancel(); })` (writable payload; return values ignored) |
| `return { text: '...' }` structured verdicts | `e.text = '...'` field writes committed through the event object |
| registration-order verdict chain | six `neo.EventPriority` levels, last-write-wins, sequential visibility, `ignoreCancelled` |
| `key:press` | `input:keyPress` |
| single `BaseEvent` face | `BaseEvent → InputEvent / DisplayEvent / StateEvent` direction classes + `e.direction` |

## 0.4.0: text API migration

0.4.0 replaces the old Text/TextBuilder/TextStyle family with a two-layer
Component/TextComponent design:

| Old (<0.4.0) | New (0.4.0+) |
| --- | --- |
| `chat.text('hi').color('red').build()` | `new Component('hi').color('red').build()` |
| `TextBuilder` / `TextStyle` | `Component` (builder; `build()` yields the value) |
| `Text` (the `chat:receive` payload) | `TextComponent` (read-only value face; `children`) |
| `chat.logText(text)` / `chat.getPlain(text)` | `chat.log(text)` (union) / the `text.plain` property |
| `JSON.stringify` rendered a segment array | renders the vanilla component tree (`{text, color, extra}`) |

See [Component](./classes/component) for the builder and
[TextComponent](./classes/textcomponent) for the value face.
