---
title: "Persistent Damage Stats"
---

A service that counts how much damage the player takes, keeps the totals
in [storage](../api/modules/core/storage) so they survive reloads and restarts, and
exposes them through a custom `/stats` client command. It deliberately
combines three subsystems — events, storage, and commands — in one
small, useful script.

## What it does

- Counts [player:damage](../api/events/player/player-damage) events:
  total hits, cumulative damage, biggest single hit, and "hard hits"
  (5 hearts of damage or more in one go).
- Writes the totals to `storage` on a 30-second timer (and once more on
  unload), not on every hit.
- Registers a `/stats` command that prints the totals, and supports
  `/stats reset`.

## The script

```text
config/neomacros/
└── macros/
    └── services/
        └── damage-tracker/
            ├── neomacro.yml
            └── index.js
```

`neomacro.yml`:

```yaml
name: damage-tracker
version: 1.0.0
author: you
description: Count damage taken, persist totals, expose /stats
permissions:
  - command
config:
  service:
    lifecycle: world
    autostart: true
```

`index.js`:

```js
// Counts damage taken, persists totals on a debounce, adds a /stats command.
const { command, chat, events, storage, thread } = neo;

const STORAGE_KEY = "stats";
const SAVE_INTERVAL_MS = 30000;
const HARD_HIT_THRESHOLD = 5;
const EMPTY_STATS = { hits: 0, total: 0, biggest: 0, hardHits: 0 };

let stats = loadStats();
let saveTimer = null;
let statsCommand = null;

export function startup() {
    events.on("player:damage", (event) => {
        stats.hits += 1;
        stats.total += event.amount;
        stats.hardHits += event.amount >= HARD_HIT_THRESHOLD ? 1 : 0;
        if (event.amount > stats.biggest) stats.biggest = event.amount;
        chat.actionbar(`Damage so far: ${stats.total.toFixed(1)}`);
    });

    saveTimer = thread.every(SAVE_INTERVAL_MS, persist);

    statsCommand = command.register({
        name: "stats",
        description: "Show or reset your persisted damage stats",
        args: {
            action: command.arg.word().optional(),
        },
        handler(ctx) {
            if (ctx.args.action === "reset") {
                stats = { ...EMPTY_STATS };
                persist();
                chat.log("Damage stats reset.");
                return;
            }
            for (const line of reportLines()) chat.log(line);
        },
    });

    for (const line of reportLines()) chat.log(line);
}

function loadStats() {
    const stored = storage.get(STORAGE_KEY);
    if (!stored || typeof stored !== "object") return { ...EMPTY_STATS };
    return {
        hits: numberOr(stored.hits),
        total: numberOr(stored.total),
        biggest: numberOr(stored.biggest),
        hardHits: numberOr(stored.hardHits),
    };
}

function numberOr(value) {
    return typeof value === "number" && Number.isFinite(value) ? value : 0;
}

function reportLines() {
    return [
        `Damage stats - hits: ${stats.hits}, total: ${stats.total.toFixed(1)}`,
        `Biggest hit: ${stats.biggest.toFixed(1)}, hard hits (>= ${HARD_HIT_THRESHOLD}): ${stats.hardHits}`,
        "Run /stats reset to start over.",
    ];
}

function persist() {
    storage.put(STORAGE_KEY, stats);
}

export function dispose() {
    persist();
    if (saveTimer) saveTimer.cancel();
    if (statsCommand) command.unregister(statsCommand);
}
```

## How it works

**The event.** [player:damage](../api/events/player/player-damage) fires
for the local player with `amount` (damage lost) and `health` (the
resulting value). The handler only touches module-scope state — cheap,
and safe to run at combat frequency. Derived categories (hard hits,
biggest hit) are computed from the same two numbers; nothing is written
to disk here.

**The debounce.** Writing on every hit would be wasteful; `thread.every`
schedules `persist` once every 30 seconds of real time and returns a
timer handle. Values passed to [storage.put](../api/modules/core/storage) must be
JSON-serializable plain data — `stats` is a flat object of numbers, so
it qualifies. Each script's store is isolated and keyed by source file,
survives `/neomacros reload` and game restarts, and is invisible to
other scripts.

**The defensive load.** `storage.get` returns `null` before the first
save, so `loadStats` falls back to a fresh zeroed object. The
`typeof`/`Number.isFinite` checks mean a corrupted or hand-edited store
degrades to zeros instead of turning the whole script into `NaN` soup.

**The command.** `command.register` takes a spec: `name`, `description`,
an optional `args` map of typed slots, and a `handler` that receives the
parsed context (`ctx.args` carries slot values, `ctx.raw` the raw
remainder). The single slot `action` is built with
`command.arg.word().optional()` — a word that may be omitted. The
handler compares it to `"reset"`; anything else prints the report.

::warning
`command.register` needs the `command` permission, declared in the
manifest under `permissions`. The first `/stats` attempt fails until
one approval with `/neomacros trust damage-tracker`.
::

**The exit.** `dispose()` persists immediately (so a quick
reload never loses the last 30 seconds), cancels the timer so it cannot
fire again, and unregisters the command by handle. Storage itself is not
removed — that is the point.

## Running it

1. The folder above lives under `.minecraft/config/neomacros/macros/services/`.
2. `/neomacros reload` loads it, and the permission is approved with
   `/neomacros trust damage-tracker`.
3. In a world, the script opens with the current totals. After a few
   hits, `/stats` prints the report; after a full game restart, another
   `/stats` shows the numbers survived.
4. `/stats reset` zeroes everything (and persists the reset).

::tip
If the command does not appear at all, `/neomacros errors` is the place
to look — an unapproved `command.register` throws, and the error screen
shows the script and line.
::

## Possible extensions

- Split by session: a second in-memory object that `dispose()` does
  *not* persist lets the report carry both "this session" and "all time".
- Healing as well: [player:heal](../api/events/player/player-heal) shares the
  same `amount` + `health` shape, so a `healed` counter can be added
  alongside.
- A `/stats export` mode: the totals read back with `storage.get` and
  printed via `chat.say`, ready to paste into chat for teammates.
