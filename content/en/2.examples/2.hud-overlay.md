---
title: "Live Status HUD"
---

A service script that keeps a three-line status panel on screen:
coordinates and facing, world facts, and vitals. This is the standard
shape of a live overlay — a throttled `tick` subscription, live handles,
and text pushed into the [hud](../api/modules/ui/hud) overlay with stable ids.

## What it does

- Twice per second (every 10 ticks), refreshes a three-line overlay:
  - position + facing, from the local player handle;
  - dimension, day, and an in-game clock, from [world](../api/modules/world/world) properties;
  - health, hunger, and FPS.
- Leaving the world (or the gap between worlds) removes the entries.

## The script

```text
config/neomacros/
└── macros/
    └── services/
        └── status-hud/
            ├── neomacro.yml
            └── index.js
```

`neomacro.yml`:

```yaml
name: status-hud
version: 1.0.0
author: you
description: Live position, world, and vitals overlay
config:
  service:
    lifecycle: world
    autostart: true
```

`index.js`:

```js
// A three-line status overlay refreshed twice per second.
const { events, hud, player, world, client } = neo;

const REFRESH_TICKS = 10; // update every 10 ticks: twice per second
const WHITE = 0xffffffff;
const GRAY = 0xffb4b4b4;
const GREEN = 0xff55ff55;

export function startup() {
    events.on("tick", (event) => {
        if (event.count % REFRESH_TICKS !== 0) return;
        refresh();
    });
}

async function refresh() {
    const self = player.self;
    if (!self) {
        await clearHud();
        return;
    }
    const pos = self.pos;
    await hud.addText("status-hud:coords",
        `XYZ ${pos.x.toFixed(1)} / ${pos.y.toFixed(1)} / ${pos.z.toFixed(1)}  (${self.facing})`,
        6, 6, WHITE);
    await hud.addText("status-hud:world",
        `${world.dimension.replace("minecraft:", "")} · day ${world.day} · ${clockText(world.time)}`,
        6, 18, GRAY);
    await hud.addText("status-hud:vitals",
        `HP ${self.health.toFixed(1)}/${self.maxHealth.toFixed(0)} · food ${self.hunger} · ${client.fps} fps`,
        6, 30, GREEN);
}

async function clearHud() {
    await hud.removeText("status-hud:coords");
    await hud.removeText("status-hud:world");
    await hud.removeText("status-hud:vitals");
}

// world.time is the time of day in ticks (0..24000); tick 0 is 06:00.
function clockText(timeOfDay) {
    const ticks = timeOfDay % 24000;
    const minutes = Math.floor((ticks % 1000) * 60 / 1000);
    const hours = Math.floor(ticks / 1000 + 6) % 24;
    return `${String(hours).padStart(2, "0")}:${String(minutes).padStart(2, "0")}`;
}

export async function dispose() {
    await clearHud();
}
```

## How it works

**The throttle.** `tick` fires every client tick — 20 times a second — and
the [tick payload](../api/events/tick/tick) carries a `count` you can
filter on. Doing a modulo check and returning is nearly free; redrawing
three overlay entries on every single tick would be waste. `tick % 10`
means the panel updates twice per second, which is plenty for text. A
`tick` subscription always carries a filter or an immediate early return.

**Stable ids.** `hud.addText(id, text, x, y, color)` registers a
persistent entry keyed by `id`, and re-adding an existing id replaces it.
That is what makes updates cheap: the script always writes the same three
ids (`status-hud:coords`, `:world`, `:vitals`) at fixed pixel positions,
so there is no accumulation and no flicker. Each line is its own entry —
one id per line keeps the geometry fully controllable.

**Live handles.** `player.self` is a live
[LocalPlayer](../api/classes/localplayer) handle: every property read
(`pos`, `facing`, `health`, `maxHealth`, `hunger`) re-reads current game
state, so no caching is needed. Outside a world it reads back as
`undefined` — the `if (!self)` branch clears the entries instead of
drawing `undefined` into the corner of the screen.

**Cleanup.** Overlay entries persist across frames until removed or the
module unloads, so unload alone would clean up. The explicit
[`dispose()`](../guide/first-script) export calls `clearHud()` anyway: it
runs on reload and makes removal visible and immediate — good hygiene for
any overlay script.

## Running it

1. The folder above lives under `.minecraft/config/neomacros/macros/services/`.
2. `/neomacros reload` loads it. Because the manifest sets
   `config.service.autostart: true` and `lifecycle: world`, the service is
   pulled up automatically on joining a world — no manual start needed.
3. In a world, the panel sits in the top-left corner. Leaving and
   rejoining shows the entries removed and redrawn.

::tip
Colors are ARGB numbers: `0xffffffff` is opaque white, `0xffb4b4b4` a
dim gray. An alpha byte of `0x80...` gives a translucent look.
::

## Possible extensions

- Low-health warning: when `self.health` drops below 6, the vitals line
  is repainted in red (`0xffff5555`) instead of green.
- Biome display: [world.biomeAt](../api/modules/world/world) called with
  `pos.floor()` coordinates, its identifier added to the world line.
- Pause while a screen is open: subscriptions to
  [screen:open](../api/events/screen/screen-open) and
  `screen:close` let the script skip refreshes while a container is up.
