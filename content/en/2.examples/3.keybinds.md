---
title: "Keybind Toggle Helper"
---

Two ways to bind the same helper — a swim assist that holds the vanilla
jump input — to a key. Variant A is a *keypress macro*: the
binding is declared in the manifest. Variant B is a *service* that
registers the binding from code with
[input.registerKeybind](../api/modules/input/input). Both appear in the vanilla
controls menu under the NeoMacros category, and both keep their toggle
state in module scope.

## What it does

- Pressing V once: the script injects a held-down state on the vanilla
  `key.jump` bind — ascent in water and ladder climbing continue
  without tapping. The action bar confirms the state.
- Pressing V again: the injected state releases.
- Either way, unloading (world leave, `/neomacros reload`) never leaves
  the key stuck down.

::warning
One variant, not both — two scripts fighting over `key.jump`
will toggle each other's state. The choice of style follows the
script's needs.
::

## Variant A — keypress macro (manifest-declared)

```text
config/neomacros/
└── macros/
    └── keypress/
        └── swim-assist/
            ├── neomacro.yml
            └── index.js
```

`neomacro.yml`:

```yaml
name: swim-assist
version: 1.0.0
author: you
description: Press V to hold jump while swimming
config:
  keypress:
    on: keypress
    key_code: key.keyboard.v
    # modifiers: [ctrl]   # require Ctrl+V instead
```

`index.js`:

```js
// Press V to hold the vanilla jump bind; press again to release.
const { input, chat } = neo;

const JUMP_BIND = "key.jump";
const ON_MSG = "Swim assist ON - press V again to release";
const OFF_MSG = "Swim assist OFF";

let enabled = false;

export function startup(event) {
    if (event.event !== "keypress") return; // only the press edge
    toggle();
}

function toggle() {
    enabled = !enabled;
    input.set(JUMP_BIND, enabled);
    chat.actionbar(enabled ? ON_MSG : OFF_MSG);
}

export function dispose() {
    if (enabled) {
        input.set(JUMP_BIND, false);
        enabled = false;
    }
}
```

## Variant B — service (programmatic keybind)

```text
config/neomacros/
└── macros/
    └── services/
        └── swim-assist-service/
            ├── neomacro.yml
            └── index.js
```

`neomacro.yml`:

```yaml
name: swim-assist-service
version: 1.0.0
author: you
description: Swim assist with the keybind registered from code
config:
  service:
    lifecycle: world
    autostart: true
```

`index.js`:

```js
// Same helper; the keybind is registered from code at startup.
const { input, chat } = neo;

const BIND_KEY = "key.keyboard.v";
const JUMP_BIND = "key.jump";
const ON_MSG = "Swim assist ON - press V again to release";
const OFF_MSG = "Swim assist OFF";

let enabled = false;
let binding = null;

export function startup() {
    binding = input.registerKeybind(BIND_KEY, () => {
        enabled = !enabled;
        input.set(JUMP_BIND, enabled);
        chat.actionbar(enabled ? ON_MSG : OFF_MSG);
    });
    chat.log(`Swim assist loaded - press ${BIND_KEY} to toggle.`);
}

export function dispose() {
    if (enabled) {
        input.set(JUMP_BIND, false);
        enabled = false;
    }
    if (binding) {
        input.unregister(binding);
        binding = null;
    }
}
```

## How it works

**Variant A: the manifest does the wiring.** `config.keypress` declares
the trigger edge (`on: keypress` — the others are `keydown` and `keyup`)
and a suggested initial binding (`key_code`). `key_code` is only a
suggestion: the real binding lives in the vanilla controls menu like any
other keymapping, and the player can rebind it there. Each trigger calls
`startup(event)` with `{ event, key, code, clicks, modifiers }` —
`event.event` is the edge name, which the guard checks so a
`keydown`/`keyup` trigger can never fire the toggle by accident.

**Variant B: the code does the wiring.**
`input.registerKeybind(keyName, sink)` takes a vanilla key name and a
callback, and returns a subscription handle. The binding is created when
the service starts — which also means it can be computed (different keys
per configuration) instead of fixed in a manifest.

**The injection.** `input.set(bindName, down)` injects the state of a
vanilla key *bind* by name (`key.jump`, `key.use`, `key.sprint`, …) —
as if the player were holding it. This is the difference between the two
`input` families here: `registerKeybind`/`unregister` manage *your*
bindings, `set`/`press`/`release`/`hold` drive *the game's* inputs.

**State and cleanup.** `enabled` lives at module scope — top-level code
runs once per load, and each trigger (or keybind sink) mutates the same
variable. The `dispose()` export releases the injected bind and, in
variant B, unregisters the binding. Without it, a reload while enabled
would leave `key.jump` held down forever.

::note
`registerKeybind` sinks repeat while the key is held (vanilla click
semantics). Held for a second, V flips the toggle many times. The
keypress-macro variant has the same practical shape, so
both variants want a discrete tap.
::

## Running it

1. One variant is picked, and its folder goes under the matching directory
   (`macros/keypress/` for A, `macros/services/` for B).
2. `/neomacros reload` loads the script; a joined world is where it runs.
3. In water, a tap of V holds the ascent even with every key released;
   a second tap releases it.
4. Options → Controls → Key Binds lists the binding under the NeoMacros
   category, and it is rebindable there.

## Possible extensions

- Toggle by double-tap: variant A's payload carries `clicks` — requiring
  `event.clicks >= 2` before toggling guards against accidental presses.
- A different injected bind: `key.jump` swapped for `key.sprint` makes a
  permanent-sprint toggle, and a `player.self.inWater` gate keeps it to
  swimming only.
- State on the HUD: the actionbar line replaced by a
  persistent [hud.addText](../api/modules/ui/hud) entry that appears only while
  enabled.
