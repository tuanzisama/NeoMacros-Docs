NeoMacros is a client-side Fabric mod that runs ECMAScript (JavaScript) inside the Minecraft game. Scripts are ordinary `.js` ES modules executed directly by GraalJS, with real promises, `async`/`await`, and a dedicated event loop for every script; there is no transpiling and no build step.

## Requirements

Installation requires four things:

- **Minecraft** (client) on a version NeoMacros builds for. Releases cover a wide range, from 1.18.2 through the 26.x line.
- **Fabric Loader** installed for that game version.
- **Fabric API** matching the game version.
- **The NeoMacros jar** itself, downloaded from the [releases page](https://github.com/tuanzisama/NeoMacros/releases). File names look like `neomacros-<mc>-fabric-<version>.jar`; the build to download is the one whose Minecraft version matches the game. The version carries its channel (`0.1.0` release, `0.1.0-dev.123+abc1234` dev, `0.1.0-canary.45+def5678` canary, `0.1.0-local` self-built) — see [Downloads & Channels](/en/guide/downloads-and-channels).

## Installation

1. Fabric Loader is installed for the current Minecraft version, if not already present.
2. The NeoMacros jar and the matching Fabric API jar go into the `mods` folder.
3. On first launch, NeoMacros creates its working directory at `config/neomacros/` and the script root at `config/neomacros/macros/`.

## Folder layout

Everything a script touches lives under the game directory:

```text
.minecraft/
└── config/
    └── neomacros/
        ├── config.json    # mod settings, including trust decisions
        └── macros/        # your scripts, one folder per script
            ├── keypress/  # scripts bound to key presses
            ├── event/     # scripts driven by declared game events
            └── services/  # long-running background scripts
```

Each script folder holds a `neomacro.yml` manifest (or `neomacro.json`) plus its entry file. The category folder decides how the script is triggered: a `keypress` script fires on a key edge, an `event` script fires on the events it declares, and a `service` starts once and keeps itself alive.

## Client commands

Four client commands cover the whole management workflow:

| Command | Purpose |
| --- | --- |
| `/neomacros list` | Show the scripts that are currently loaded |
| `/neomacros reload` | Rescan the macros folder and apply your changes |
| `/neomacros trust <script>` | Grant a script the capabilities it declared |
| `/neomacros errors` | Open the screen listing recent script failures |

The everyday edit loop is: save the file, run `/neomacros reload`, observe the result.
