title: "Getting Started"
---

NeoMacros is a client-side Fabric mod that runs ECMAScript (JavaScript) inside your Minecraft game. Scripts are ordinary `.js` ES modules executed by GraalJS, so you get real promises, `async`/`await`, and a dedicated event loop for every script — no transpiling, no build step, just files in a folder.

## Check the requirements

You need four things before installing:

- **Minecraft** (client) on a version NeoMacros builds for. Releases cover a wide range, from 1.18.2 through the 26.x line.
- **Fabric Loader** installed for that game version.
- **Fabric API** matching your game version.
- **The NeoMacros jar** itself, downloaded from the [releases page](https://github.com/tuanzisama/NeoMacros/releases). File names look like `neomacros-<mc>-fabric-<version>.jar` — pick the build whose Minecraft version matches yours.

## Install the mod

1. Install Fabric Loader for your Minecraft version, if you have not already.
2. Drop the NeoMacros jar and the matching Fabric API jar into your `mods` folder.
3. Launch the game once. NeoMacros creates its working directory at `config/neomacros/` and the script root at `config/neomacros/macros/`.

## Learn the folder layout

Everything a script touches lives under the game directory:

```text
.minecraft/
└── config/
    └── neomacros/
        ├── config.json    # mod settings, including trust decisions
        └── macros/        # your scripts, one folder per script
            ├── keypress/  # scripts bound to key presses
            ├── event/     # scripts driven by declared game events
            └── services/  # long-running background scripts
```

Each script folder holds a `neomacro.yml` manifest (or `neomacro.json`) plus its entry file. The category folder decides how the script is triggered: a `keypress` script fires on a key edge, an `event` script fires on the events it declares, and a `service` starts once and keeps itself alive.

## Manage scripts with the client commands

Four client commands cover the whole management workflow:

| Command | Purpose |
| --- | --- |
| `/neomacros list` | Show the scripts that are currently loaded |
| `/neomacros reload` | Rescan the macros folder and apply your changes |
| `/neomacros trust <script>` | Grant a script the capabilities it declared |
| `/neomacros errors` | Open the screen listing recent script failures |

The edit loop you will use constantly is: save the file, run `/neomacros reload`, observe the result.
