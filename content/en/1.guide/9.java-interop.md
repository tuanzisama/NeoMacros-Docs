---
title: "Java Interop"
---

::warning
Granting the `java` permission hands the script full host access: every class on the JVM, no filtering, arbitrary code through reflection. It is meant only for scripts that have been read and understood.
::

NeoMacros keeps scripts behind curated facades, but `neo.java` is the escape hatch past them — a bridge onto the host JVM the game runs on. It comes into play when a facade does not cover a vanilla internal, when a Java library is needed, or when following a community recipe written against Minecraft's own classes.

## Class lookup by binary name

`java.type` resolves one class by its binary (dot-separated) name and returns a class proxy. Minecraft classes are named in Mojmap; the mapping layer translates at the call site, so the mappings-era names apply regardless of the runtime jar.

```js
const { java, chat } = neo;

const UUID = java.type('java.util.UUID');
const id = UUID.randomUUID();          // statics dispatch straight off the proxy
chat.log(id.toString());               // object proxies dispatch instance methods
```

The class proxy exposes static fields as values and static methods as callables. Constructing instances goes through the proxy's `new` member:

```js
const File = java.type('java.io.File');
const f = File.new('config/neomacros');
```

Every host object that crosses back into the script is wrapped as an object proxy: member reads reach the real fields and methods underneath. `java.proxy(interfaces, handlers)` goes the other direction, building a host object whose methods dispatch to the script's functions.

## Collection converters

Script arrays and Java collections do not interoperate implicitly. Three converters cover it:

```js
java.toList(['a', 'b']);                    // script array → live java.util.List
java.fromList(someJavaCollection);          // host collection → script array
java.toArray(['a'], 'java.lang.String');    // script array → typed host array
```

## Exact signatures with reflect

Where `java` proxies the public surface, `neo.reflect` resolves exact declarations — private members and specific overloads included:

```js
const { reflect } = neo;

const m = reflect.method(target, 'getSender', ['int']);   // exact overload
const v = reflect.invoke(m, target, [42]);                // omit target for statics
const obj = reflect.newInstance('java.util.ArrayList');
reflect.className(v);                                     // runtime class of any value
```

Members that proxy lookup cannot see are called through reflection. It rides the same `java` permission.

## The raw client entry point

The usual starting point for vanilla internals is the client instance itself. `neo.client.minecraft` (java permission required) exposes the raw client as an object proxy; it is equivalent to `java.type('net.minecraft.client.Minecraft').getInstance()`. Most Minecraft-class recipes start there. Game state belongs on the main thread, so reads and writes go inside `thread.runOnMain` (see [Async and Threading](./async-threading)).
