---
title: "MCP Agent Server"
---

NeoMacros ships a built-in [MCP](https://modelcontextprotocol.io) (Model Context Protocol) server. An AI agent — Claude Code, Codex, ZCode, or any MCP client — connects over Streamable HTTP and can read logs, inspect game state, and drive the client, running against the same internals the scripts use. This page covers starting it, wiring an agent in, and three everyday scenarios.

## Requirements

- A NeoMacros jar on any of the supported versions (`1.21.6`, `26.1.2`, `26.2`, `26.3`), installed and launched.
- An MCP-capable agent on the same machine (the server binds the loopback by default).
- The game running — in a world for the state and control tools; the log tools work anywhere.

## Starting the server

The server is off by default. In-game:

```
/neomacros mcp start
```

The command prints everything an agent config needs:

```
MCP server running on port 30637 (sessions: 0)
Endpoint: http://127.0.0.1:30637/mcp
Bearer token: 5cdccad103d9d99fbdbd27cc8d45f8ed
```

`/neomacros mcp stop` stops it, `token` prints the connection details again, and `regen` rotates the token and disconnects every live session. A permanent setup lives in the config (`core.mcp` section of `config/NeoMacros/config.json`, or ModMenu → NeoMacros settings → MCP Agent Server); with it enabled, the server comes up with the game.

::tip
The token is generated on first start and persisted, so it survives restarts. If the token ever ends up somewhere public, `/neomacros mcp regen` invalidates it immediately.
::

## Endpoint check with curl

One curl round-trip proves the server, port, and token are good:

```bash
curl -s -X POST http://127.0.0.1:30637/mcp \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"smoke","version":"0"}}}'
```

A healthy server answers with `serverInfo` (`"name":"neomacros"`) and an `Mcp-Session-Id` response header. Connection refused means the server is not running (or a different port); 401 means the token does not match.

## Connecting an agent

Claude Code:

```bash
claude mcp add --transport http neomacros http://127.0.0.1:30637/mcp \
  --header "Authorization: Bearer <token>"
```

Every other MCP client wants the same two facts: an HTTP endpoint at `/mcp` and an `Authorization: Bearer <token>` header. Once added, the quickest check is asking the agent to *list its available tools* — the `get_*`, `list_modules`, `send_chat`, and friends from the table below should appear.

## Three everyday scenarios

**Debugging a misbehaving script.** A prompt like *"Something in my scripts is spamming errors — check the console and logs, find the cause, and tell me which script to fix."* has the agent reading `get_console` (script output including the DevTools session) and `get_logs` (filter by logger or level), spotting the stack, then probing live state with `eval_script` before touching the file. After an edit, `stop_module` + `start_module` reloads the script, and another look at `get_console` confirms the fix.

**Questions about the game.** *"What dimension am I in, what time is it, and what mobs are within 16 blocks?"* maps to `get_world` (dimension, time, weather, entities by radius), and *"what do I have on me?"* maps to `get_player` + `get_inventory` (held stack, slots, and the open container if one is open). `get_screen` reports the open screen or dialog — useful when an agent is helping drive a menu.

**Letting it act.** With the control group on, the agent can `send_chat`, `run_command` (same as typing `/...` in chat), `inject_key`, and manage scripts. Everything acts *as you* — a `run_command` is indistinguishable from you typing it. `eval_script` is the strongest and the most dangerous: arbitrary JavaScript with full `neo.*` access, equivalent to a fully trusted script.

## The tools

| Tool | Group | What it does |
| --- | --- | --- |
| `get_logs` | logs | Log lines with incremental replay by sequence (`after`), level and logger filters. Captures NeoMacros loggers by default; the full game log when `logCapture` is `all`. |
| `get_console` | logs | Script console output (`console.log` and friends, including the DevTools session). |
| `get_network` | logs | Recorded `neo.net` requests with status, timing, and body previews. |
| `get_tasks` | logs | Active script tasks plus the finished history. |
| `get_player` | state | Local player snapshot: position, health, hunger, effects, armor. |
| `get_inventory` | state | Held stack, inventory slots, and the open container when one is open. |
| `get_screen` | state | The open screen, the open dialog with its actions/inputs, chat draft text. |
| `get_world` | state | Dimension, time, weather, and entities within a radius. |
| `list_modules` | control | Every discovered script with running/enabled state and load errors. |
| `start_module` / `stop_module` | control | Load or unload a script (the saved autostart intent stays untouched). |
| `send_chat` | control | Send one chat message as the player. |
| `run_command` | control | Run a command as the player (same as typing `/...` in chat). |
| `inject_key` | control | Inject a raw key press or release. |
| `eval_script` | eval | Evaluate JavaScript with full `neo.*` access — in the shared DevTools session or inside a named script's context. |

Game-state and control tools return an `isError` result when the client is not inside a loaded world. Log tools work everywhere.

## Security model

- **Off by default.** Nothing listens until the server is started (or `autoStart` is enabled).
- **Loopback bind.** The listener answers on `127.0.0.1` only unless `core.mcp.listen` is changed; the Host and Origin checks reject rebinding attempts either way.
- **Bearer token.** Generated on first start, persisted in `config/NeoMacros/config.json`, required on every request. `regen` rotates it and kicks connected sessions.
- **Group switches.** `groupLogs`, `groupState`, `groupControl`, and `groupEval` remove whole tool groups from `tools/list` when off — `groupEval` governs whether agents can run arbitrary JavaScript.

## Configuration reference (`core.mcp`)

| Key | Default | Meaning |
| --- | --- | --- |
| `enabled` | `false` | Last start/stop intent; the server restarts with this state. |
| `autoStart` | `false` | Start with the client regardless of `enabled`. |
| `port` | `30637` | TCP port (the web panel uses 30636). |
| `listen` | `127.0.0.1` | Bind address (`127.0.0.1`, `0.0.0.0`, `::1`). |
| `token` | *(generated)* | The bearer token; blank means generated on next start. |
| `logCapture` | `mod` | `mod` captures NeoMacros loggers, `all` captures every logger. |
| `groupLogs` / `groupState` / `groupControl` / `groupEval` | `true` | Tool group switches. |

## Troubleshooting

- **401 on every request.** The agent's header does not carry the exact current token. `/neomacros mcp token` prints it for comparison; if it ever leaked, `regen` rotates it and the agent config needs the new value.
- **`unknown session` (404) mid-conversation.** The session expired (30 idle minutes) or the service restarted. Agents re-initialize automatically; a stuck client recovers by removing and re-adding the server entry.
- **`Cannot start: port in use`.** Another process holds the port; the fix is a new `core.mcp.port` plus a restart, or stopping the occupant.
- **Connection refused.** The service is not running, or the agent is not on the same machine (the default bind is loopback-only; `0.0.0.0` exposes the LAN and shifts all trust to the token).
- **Tools missing from the agent's list.** The group is disabled in config — the `group*` switches are the place to look, and a reconnect rebuilds the list (it is built per service start).
- **`isError: not inside a loaded world`.** State and control tools refuse the main menu; inside a loaded world they respond.
- **Logs look empty.** `logCapture: mod` records only the NeoMacros loggers; `all` covers the whole game log.
