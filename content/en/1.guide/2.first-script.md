# Your First Script

This page builds a complete script from scratch: a folder, a manifest, an entry file, and the reload cycle that turns edits into running code without leaving the game.

## Create the folder and manifest

Pick the category folder that matches how the script should trigger. For an event-driven script, create `config/neomacros/macros/event/hello/` and put a `neomacro.yml` manifest in it:

```yaml
name: hello            # unique ID used by commands and the trust table
version: 1.0.0
author: you            # these three fields are required
description: greets you when you join a world

config:
  event:
    on: [world:join]   # the events this script reacts to
```

`neomacro.json` is accepted too (a same-folder `neomacro.yml` wins if both exist). The top level carries identity fields only: the required `name`, `version`, and `author`, plus optional `description`, `license`, `homepage`, `supportURL`, `main` (entry file, default `index.js`), and `permissions` (covered in [Permissions and Trust](./permissions-trust)).

Behavior lives in the `config:` block. For event macros, `config.event.on` lists the events to react to; names are validated at load, so a typo is rejected immediately.

## Write the entry file

Create `index.js` in the same folder:

```js
const { chat } = neo;

export function startup(payload) {
    chat.log('Hello from my first script!');
}
```

A script is a normal ES module, and the one export NeoMacros requires is `startup` (async supported). For an event macro, every occurrence of a declared event calls `startup(payload)` — the same snapshot object a manual `events.on` handler would receive. Top-level code still runs once at load, which makes it the right place for constants and module state.

::tip
Point your editor at the published TypeScript definitions (`/neomacros.d.ts`) to get autocomplete and inline types for every `neo.*` member.
::

## Load and verify it

Run the reload command in chat:

```text
/neomacros reload
```

Then confirm the script came up:

```text
/neomacros list
```

Jump into a world to fire `world:join` and watch the greeting appear in your local chat.

## Know where errors surface

If the manifest is malformed, an event name is unknown, or `startup` is missing, the folder is skipped and the reason is recorded. If a running script throws, the error is captured and the rest of your scripts keep running. Both kinds of failures show up in `/neomacros errors` with the message and a stack trace pointing back to your file — see [Troubleshooting](./troubleshooting).

## Trigger on a key instead

Scripts under `macros/keypress/<name>/` declare their trigger edge in the manifest rather than an event:

```yaml
config:
  keypress:
    on: keydown           # keydown / keyup / keypress (the default)
    default-key: key.keyboard.j
    modifiers: [ctrl]     # optional: require ctrl/shift/alt
```

Each trigger edge calls `startup(ev)` with `ev = { event, key, code, clicks, modifiers }`, so the same entry style works:

```js
export function startup(ev) {
    neo.chat.log(`pressed ${ev.key}`);
}
```

`default-key` is a suggestion only — it seeds the initial binding and does not lock it.

## Clean up with dispose

Subscriptions created while your module loads are attributed to it and removed automatically on unload, so reloading never leaks handlers. If your script holds anything beyond subscriptions — a timer, a file handle from `neo.fs` — export an optional cleanup hook:

```js
export function dispose() {
    // extra teardown before the module is dropped
}
```

`dispose()` runs during reload and unload, after which the engine removes whatever remains. Next, make the script react to the world around you: read [Events](./modules/core/events).
