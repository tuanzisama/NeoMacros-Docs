# Client Commands

Scripts can add their own client-side chat commands. Registration goes through `neo.command` with a declarative spec, typed argument slots, and a handler that receives parsed values. Registering (and executing commands programmatically) requires the `command` permission — see [Permissions and Trust](./permissions-trust).

## Register a command

A command spec carries `name`, `description`, an optional `args` slot map, and the `handler`:

```js
const { command, chat } = neo;

export function startup() {
    command.register({
        name: 'greet',
        description: 'Greets someone, N times',
        args: {
            target: command.arg.player(),
            times: command.arg.int().defaultTo(1),
            note: command.arg.greedy().optional(),
        },
        handler(ctx) {
            const n = ctx.args.times;
            for (let i = 0; i < n; i++) {
                chat.log(`Hello, ${ctx.args.target}!`);
            }
        },
    });
}
```

Put registration in a `services` script: `startup` runs once on activation, which is exactly the shape command setup wants. After `/neomacros reload` and `/neomacros trust <script>`, type `/greet Steve 3 nice work` in chat to see it fire.

## Build typed argument slots

Slots are created through `command.arg`, in the order they should consume input. Eight kinds exist:

| Kind | Consumes |
| --- | --- |
| `int()` | An integer |
| `float()` | A decimal number |
| `bool()` | `true` / `false` |
| `word()` | A single token |
| `string()` | A single token, kept as a string |
| `greedy()` | Everything that remains |
| `player()` | A player-style name token |
| `pos()` | A block position |

Parsing walks the slots in declaration order against the raw remainder, so the first slot takes the first token and so on. Two modifiers change a slot's strictness:

- `.optional()` — missing input falls back instead of raising (the key stays absent rather than becoming a placeholder).
- `.defaultTo(v)` — missing input falls back to `v`.

A required slot with no token left raises, and the command fails with a parse error. `greedy` is best placed last: it swallows the entire remaining string, spaces included.

## Read the handler context

The handler receives one context object with two members:

- `ctx.args` — the parsed, typed values, keyed by slot name (`ctx.args.times` is a number because the slot was `int()`).
- `ctx.raw` — the whole remainder string after the command name, untouched.

`ctx.raw` is handy for passing text along verbatim or logging exactly what the player typed.

## Unregister when it should go away

`command.register` returns an opaque handle. Pass it — or the command's name — to unregister:

```js
const handle = command.register({ name: 'greet', description: '...', handler(ctx) {} });

command.unregister(handle);    // by handle
command.unregister('greet');   // or by name
```

Unregistering itself needs no permission. For commands that should exist only while a condition holds, register and unregister around the condition instead of leaving the command live. The full member list is on the [command facade](../api/modules/ui/command) page.
