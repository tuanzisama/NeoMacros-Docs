title: "Events"

NeoMacros scripts are event-driven: the game publishes snapshots of what is happening, and handlers decide what to do with them. This page covers the subscription toolkit on `neo.events`, cancellation and rewriting on the interception channel, and how to keep expensive events cheap.

## Event directions

Every event declares its traffic direction, which tells you what a handler may do with it:

| Direction | Meaning | Abilities |
| --- | --- | --- |
| `c2s` | The client is about to act (key press, chat send, block/entity interaction) | Cancellable; `chat:send` can also rewrite the message |
| `s2c` | Server-originated content is about to land (chat, titles, sign editor) | Cancellable; whitelisted fields rewritable |
| `local` | Client-derived state (tick, vitals, world, screen transitions) | Observation only, never cancellable |

`e.direction` exposes the literal on every payload, and the payload interfaces chain through the direction middle classes — `e instanceof neo.InputEvent` discriminates c2s events at runtime.

## Subscriptions with events.on

`events.on(name, handler)` registers an asynchronous listener. The handler runs on the script's event loop and receives the payload as a frozen snapshot object:

```js
const { events, chat } = neo;

const handle = events.on('player:health', (payload) => {
    chat.actionbar(`health: ${payload.health}`);
});
```

Event names follow the `domain:name` convention — `chat:receive`, `player:health`, `input:keyPress`, `world:sound`. The bare built-in `tick` is the one exception. Wildcards work too: `domain:*` matches a whole domain and `*` matches everything (high-traffic names such as `tick`, `world:sound`, and `world:blockUpdate` are excluded from wildcard dispatch by default).

Unsubscribing passes the handle back:

```js
events.off(handle);              // by handle
events.off('player:health');     // or by event name
```

Subscriptions created while a module is loading are attributed to that module and unsubscribed automatically when it unloads.

## Manifest-declared subscriptions

An event macro declares its events under `config.event.on`, and the engine calls the exported `startup(payload)` for each occurrence — no manual wiring needed. Manual `events.on` subscriptions coexist with the declared ones and are the tool of choice for services, wildcard listeners, and subscriptions whose lifetime is controlled by the script. The declared style is covered in [Your First Script](./first-script).

## Intercepting with onSync: cancel and rewrite

Cancellable events accept synchronous subscriptions made with `events.onSync`. The callback runs on the dispatch thread and receives the payload in writable form: rewrite whitelisted fields directly, and cancel with `e.cancel()` or the writable `e.cancelled` accessor. Return values are ignored — the effect travels through the event object.

```js
const { events } = neo;

events.onSync('chat:send', (e) => {
    if (e.message.includes('secret')) {
        e.cancel();                     // veto the send
    }
    if (e.message === 'typo') {
        e.message = 'fixed';            // rewrite the outgoing text
    }
});

events.onSync('screen:signEdit', (e) => {
    e.lines = ['signed by neo', '', '', ''];
    e.closeScreen = true;               // skip the editor, submit directly
});
```

Sync callbacks must stay short: nothing in the game proceeds past them until they return, so the callback decides and mutates — no `await`, no loops.

### Priorities

Several scripts can intercept the same event. `options.priority` orders the chain — `LOWEST` runs first, `HIGHEST` runs last with the final say, and `MONITOR` is observation-only (its writes and cancel changes are dropped with a warning). Pass the `neo.EventPriority` constants, not strings:

```js
events.onSync('chat:title', (e) => {
    e.text = 'redirected';
}, { priority: neo.EventPriority.HIGH, ignoreCancelled: true });
```

Handlers later in the chain **observe earlier writes** and can override them, and the cancellation state follows last-write-wins: a later handler may undo an earlier `cancel()` by setting `e.cancelled = false`. `options.ignoreCancelled: true` skips the handler entirely once the event is already cancelled.

## Waiting for a single occurrence

Three helpers cover one-shot patterns:

- `events.once(name, handler)` fires exactly once and unsubscribes itself.
- `events.waitFor(name)` returns a promise that settles with the next payload.
- `events.waitForUntil(name, filter, timeoutMillis)` resolves with the first payload matching `filter` and rejects once the timeout passes. The filter runs on the dispatch thread, so it needs to stay cheap.

```js
const { events, chat } = neo;

try {
    await events.waitForUntil('player:health', (p) => p.health < 6, 30000);
    chat.actionbar('low health!');
} catch {
    chat.log('no low-health moment within 30s');
}
```

## Filtering high-frequency events

Events like `tick` fire twenty times per second, and `world:blockUpdate` fires for every block state change the client receives. A handler that does real work on every firing will dominate the script's loop. The guard is an early return:

```js
const { events, chat } = neo;

let n = 0;

events.on('tick', () => {
    n += 1;
    if (n % 20 !== 0) return;        // bail out on 19 of every 20 ticks
    chat.actionbar('once a second');
});
```

The `tick` payload carries the tick `count`, so `payload.count` works as the gate in place of a local counter. Whatever the guard, the body should touch as little as possible.

## Custom events

Scripts can publish too. `events.register('myscript:burst')` reserves a namespaced name (it cannot shadow a built-in domain), after which `events.emit('myscript:burst', payload)` delivers to other listeners on the async channel. Payload keys must avoid the reserved words `type`, `timestamp`, `cancellable`, and `direction`.

Payload field tables for all built-in events live in the API: the [events facade](../api/modules/core/events), [chat:receive](../api/events/chat/chat-receive), [player:health](../api/events/player/player-health), and the rest of the event catalog under it.
