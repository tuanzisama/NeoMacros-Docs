---
title: "MCP Agent Server"
---

NeoMacros ships a built-in [MCP](https://modelcontextprotocol.io) (Model Context Protocol) server. An AI agent — Claude Code, Codex, ZCode, or any MCP client — connects over Streamable HTTP and can read logs, inspect game state, and drive the client, running against the same internals your scripts use. This page walks through starting it, wiring an agent in, and three everyday scenarios.

## What you need

- A NeoMacros jar on any of the supported versions (`1.21.6`, `26.1.2`, `26.2`, `26.3`), installed and launched.
- An MCP-capable agent on the same machine (the server binds the loopback by default).
- The game running — in a world for the state and control tools; the log tools work anywhere.

## Start the server

The server is off by default. In-game:

```
/neomacros mcp start
```

The command prints everything an agent config needs:

```
MCP server running on port 30637 (sessions: 0)
Endpoint: http://127.0.0.1:30637/mcp
Bearer token: 5cdccad103d9d99fbdbd27cc8d45f8ed
```

`/neomacros mcp stop` stops it, `token` prints the connection details again, and `regen` rotates the token and disconnects every live session. For a permanent setup, enable it in the config (`core.mcp` section of `config/NeoMacros/config.json`, or ModMenu → NeoMacros settings → MCP Agent Server) and it comes up with the game.

::tip
The token is generated on first start and persisted, so it survives restarts. If you ever paste it into something public, `/neomacros mcp regen` invalidates it immediately.
::

## Verify the endpoint before blaming the agent

One curl round-trip proves the server, port, and token are good:

```bash
curl -s -X POST http://127.0.0.1:30637/mcp \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"smoke","version":"0"}}}'
```

A healthy server answers with `serverInfo` (`"name":"neomacros"`) and an `Mcp-Session-Id` response header. Connection refused means the server is not running (or a different port); 401 means the token does not match.

## Connect an agent

Claude Code:

```bash
claude mcp add --transport http neomacros http://127.0.0.1:30637/mcp \
  --header "Authorization: Bearer <token>"
```

Every other MCP client wants the same two facts: an HTTP endpoint at `/mcp` and an `Authorization: Bearer <token>` header. After adding, ask the agent to *list its available tools* — you should see the `get_*`, `list_modules`, `send_chat`, and friends from the table below.

## Three everyday scenarios

**Debug a misbehaving script.** Ask the agent: *"Something in my scripts is spamming errors — check the console and logs, find the cause, and tell me which script to fix."* It reads `get_console` (script output including the DevTools session) and `get_logs` (filter by logger or level), spots the stack, then probes live state with `eval_script` before touching the file. After you edit the script, it can `stop_module` + `start_module` to reload it and re-check `get_console` to confirm the fix.

**Ask about the game.** *"What dimension am I in, what time is it, and what mobs are within 16 blocks?"* maps to `get_world` (dimension, time, weather, entities by radius), and *"what do I have on me?"* maps to `get_player` + `get_inventory` (held stack, slots, and the open container if one is open). `get_screen` reports the open screen or dialog — useful when an agent is helping you drive a menu.

**Let it act.** With the control group on, the agent can `send_chat`, `run_command` (same as typing `/...` in chat), `inject_key`, and manage scripts. Everything acts *as you* — a `run_command` is indistinguishable from you typing it. `eval_script` is the strongest and the most dangerous: arbitrary JavaScript with full `neo.*` access, equivalent to a fully trusted script.

## The tools

| Tool | Group | What it does |
| --- | --- | --- |
| `get_logs` | logs | Log lines with incremental replay by sequence (`after`), level and logger filters. Captures NeoMacros loggers by default; the full game log when `logCapture` is `all`. |
| `get_console` | logs | Script console output (`console.log` and friends, including the DevTools session). |
| `get_network` | logs | Recorded `neo.net` requests with status, timing, and body previews. |
| `get_tasks` | logs | Active script tasks plus the finished history. |
| `get_player` | state | Local player snapshot: position, health, hunger, effects, armor. |
| `get_inventory` | state | Held stack, inventory slots, and the open container when one is open. |
| `get_screen` | state | The open screen, the open dialog with its actions/inputs, chat draft text. |
| `get_world` | state | Dimension, time, weather, and entities within a radius. |
| `list_modules` | control | Every discovered script with running/enabled state and load errors. |
| `start_module` / `stop_module` | control | Load or unload a script (the saved autostart intent stays untouched). |
| `send_chat` | control | Send one chat message as the player. |
| `run_command` | control | Run a command as the player (same as typing `/...` in chat). |
| `inject_key` | control | Inject a raw key press or release. |
| `eval_script` | eval | Evaluate JavaScript with full `neo.*` access — in the shared DevTools session or inside a named script's context. |

Game-state and control tools return an `isError` result when the client is not inside a loaded world. Logs tools work everywhere.

## Security model

- **Off by default.** Nothing listens until you start it (or enable `autoStart`).
- **Loopback bind.** The listener answers on `127.0.0.1` only unless you change `core.mcp.listen`; the Host and Origin checks reject rebinding attempts either way.
- **Bearer token.** Generated on first start, persisted in `config/NeoMacros/config.json`, required on every request. `regen` rotates it and kicks connected sessions.
- **Group switches.** `groupLogs`, `groupState`, `groupControl`, and `groupEval` remove whole tool groups from `tools/list` when off — turn off `groupEval` if you do not want agents running arbitrary JavaScript.

## Configuration reference (`core.mcp`)

| Key | Default | Meaning |
| --- | --- | --- |
| `enabled` | `false` | Last start/stop intent; the server restarts with this state. |
| `autoStart` | `false` | Start with the client regardless of `enabled`. |
| `port` | `30637` | TCP port (the web panel uses 30636). |
| `listen` | `127.0.0.1` | Bind address (`127.0.0.1`, `0.0.0.0`, `::1`). |
| `token` | *(generated)* | The bearer token; blank means generated on next start. |
| `logCapture` | `mod` | `mod` captures NeoMacros loggers, `all` captures every logger. |
| `groupLogs` / `groupState` / `groupControl` / `groupEval` | `true` | Tool group switches. |

## Troubleshooting

- **401 on every request.** The agent's header does not carry the exact current token. Re-run `/neomacros mcp token` and compare; if it ever leaked, `regen` and update the agent config.
- **`unknown session` (404) mid-conversation.** The session expired (30 idle minutes) or the service restarted. Agents re-initialize automatically; if a client gets stuck, remove and re-add the server entry.
- **`Cannot start: port in use`.** Another process holds the port — change `core.mcp.port` and restart, or stop the occupant.
- **Connection refused.** The service is not running, or the agent is not on the same machine (the default bind is loopback-only; `0.0.0.0` exposes the LAN and shifts all trust to the token).
- **Tools missing from the agent's list.** The group is disabled in config — check the `group*` switches, then reconnect (the tool list is built per service start).
- **`isError: not inside a loaded world`.** Join a world; state and control tools refuse the main-menu.
- **Logs look empty.** `logCapture: mod` only records NeoMacros loggers; set it to `all` to capture the whole game log.
