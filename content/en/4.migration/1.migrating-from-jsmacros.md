---
title: "Migrating from JsMacros"
---

NeoMacros speaks the same language as JsMacros — plain ES modules on a JS
engine — but the API around it is new: `neo.*` facades instead of JsMacros
globals, camelCase `domain:name` event names instead of `UPPER_SNAKE`,
async-first I/O, and a manifest-based script layout. If you have a stack
of JsMacros 1.x scripts, there are two ways forward, and you can mix them
freely:

- **Run them today with the compat layer.** [jsmacros-compat](#install-the-compat-layer)
  reimplements the JsMacros 1.9.2 script API on top of `neo.*`. Code like
  `Player.getPlayer()` and `JsMacros.on('Tick', ...)` keeps working with
  minimal changes.
- **Rewrite against the native API** ([going native](#going-native)) when
  you want the idiomatic surface. That is the durable path, and the compat
  layer makes it incremental: port one script at a time, and only the parts
  worth porting.

## Install the compat layer

1. [Download the compat pack](https://neomacros.tuanzi.ink/downloads/jsmacros-compat.zip) (~105 KB)
   and extract it — you get a single `jsmacros-compat` folder.
2. Copy that folder into your script root, `config/neomacros/macros/`.
3. Import it once at the top of every script that uses the old API:

```js
import './jsmacros-compat/src/index.js';
```

The import mounts the full JsMacros global surface — `JsMacros`, `Player`,
`World`, `Chat`, `Client`, `Time`, `KeyBind`, `Hud`, `FS`, `GlobalVars`,
`Request`, `Reflection`, `JavaUtils`, `JavaWrapper`, `PositionCommon`,
`Utils`, `Color` — and it is idempotent, so many scripts can import it in
parallel without double-mounting.

::note
The compat layer is a pure script-level library: it ships no Java code,
lives entirely inside your script folder, and uninstalls by deleting the
folder.
::

For editor and `tsc` support, add
`jsmacros-compat/types/jsmacros-compat.d.ts` to your `tsconfig`.

## Mind the script layout

The compat layer bridges the API surface, not the hosting model. JsMacros
executed every `.js` file dropped into its scripts folder; NeoMacros loads
**one folder per script**, each with a `neomacro.yml` manifest, sorted by
trigger type into `keypress/`, `event/`, or `services/` (see
[folder layout](../guide/getting-started)). The practical mapping:

- A JsMacros script that calls `JsMacros.on(...)` at the top level and runs
  until the game closes → drop it into `services/`. Services start once and
  keep themselves alive, and the old self-registration style keeps working
  through the compat layer.
- A script that should wake only on declared game events → convert it to an
  `event` macro that declares its events under `config.event.on` (see
  [Your First Script](../guide/first-script)) and port the body whenever
  convenient.
- A keybind script → `keypress/` with a `key_code`, or keep using the
  compat `KeyBind` surface.

## What works out of the box

- **Read surface** (synchronous, live handles): player/world/entity/block
  queries, `Chat.log/say/actionbar`, `Time.time()`, key injection via
  `KeyBind`, `GlobalVars` (backed by `storage`), the four-tier entity
  helper chain plus 75 specialized entity shells, the inventory surface
  plus 16 specialized inventory shells, `Color`, `PositionCommon`, and
  base64 in `Utils`.
- **Event bridge**: `JsMacros.on/once/off/waitForEvent` with the
  `(event, context)` callback shape, 36 bridged event names plus the legacy
  `UPPER_SNAKE` aliases, per-event payload adapters, custom events, and
  JS-side filterers.
- **Render**: `Hud.createDraw2D` (text elements) and `Hud.createDraw3D`
  (boxes, lines, points), including the JsMacros register lifecycle.
- **Escape hatches**: `Reflection`, `JavaUtils`, and `Client.getMinecraft`
  — gated by the NeoMacros java permission, exactly like their JsMacros
  equivalents.

## Add await where a promise comes back

NeoMacros is async-first. These JsMacros-synchronous surfaces keep their
signatures but return promises — add `await`:

| JsMacros call | Compat return |
| --- | --- |
| `FS.*` (all filesystem access) | `Promise<...>` |
| `Request.get/post/create(url).get()` | `Promise<ResponseCompat>` (its `text()/json()/byteArray()` are async) |
| `Time.sleep(ms)` | `Promise<void>` |
| `Client.waitTick([n])`, `Client.runOnMainThread(fn, true)` | `Promise<void>` / `Promise<unknown>` |
| `Inventory.click/dropSlot/quick/swapHotbar/split/grabAll/closeAndDrop/close` | `Promise<void>` |
| `ClientPlayer.dropHeldItem`, interaction-manager actions | `Promise<void>` |

::warning
An un-awaited `FS.exists(p)` inside an `if` is always truthy — the branch
checks the promise object, not the file. Migrate call sites deliberately,
one by one.
::

## What is not available

Every JsMacros member that has no NeoMacros equivalent **keeps its name
and throws `UnimplementedError` when called** — nothing is silently
missing, so a script either works or fails loudly at the exact call site.
The highlights:

| Missing area | Detail |
| --- | --- |
| Packet access | `RecvPacket`/`SendPacket` events and any packet-level utilities — NeoMacros exposes no packet layer |
| `Title` / `SignEdit` events | NeoMacros has no title or sign-editing event (only the local `chat.actionbar` output) |
| Inventory click events | The `ClickSlot` event family — NeoMacros exposes no inventory events |
| Screens & textures | Creating or controlling screens (`ScriptScreen`, `FHud.createScreen/openScreen`) |
| Runtime Java compilation | Compiling Java source at runtime |
| Specialized species states | Parts of the 75 entity shells stay stub-backed where NeoMacros exposes no read |

The exhaustive list — 1,157 class-level members, 24 event-payload members,
and 19 unsupported event names, every one with a documented reason — is
`docs/missing-apis.md` inside the [compat download](https://neomacros.tuanzi.ink/downloads/jsmacros-compat.zip).

## Behavioral differences worth knowing

These do not throw — they just behave differently from JsMacros:

| Difference | What changes |
| --- | --- |
| FS path root | Paths resolve against the game directory, not the scripts folder |
| Entity reads are live | Helpers re-read through live handles instead of snapshotting at creation; vanished entities read as `null`/`undefined` |
| Display names | `getName`/`getDefaultName` derive from the id (`minecraft:deepslate_bricks` → `Deepslate Bricks`) — no translation lookup |
| `isDay` / `isNight` | Fixed vanilla window: night spans ticks 13000–23000 |
| Message rewriting | `RecvMessage.text` / `SendMessage.message`: reading works, assignment throws — NeoMacros supports cancelling, not rewriting |
| Custom events | Cannot be cancelled |
| `ANYTHING` wildcard | Skips high-traffic events (`tick`, `world:sound`, `world:blockUpdate`) by default |
| `HeldItemChange.offHand` | Always `false` — the held-item event fires for the main hand only |
| Styled text | `Chat.log` with styled text renders via legacy `§` codes; hover/click styling is dropped |
| World scans | `iterateSphere`/`iterateBox` are plain JS loops — much slower than the native scanner on large volumes |

The full list of approximations and signature deviations (section 8 of
`docs/missing-apis.md`) ships in the
[compat download](https://neomacros.tuanzi.ink/downloads/jsmacros-compat.zip).

## Going native

When you are ready to retire the compat layer from a script, the mapping is
mostly mechanical:

| JsMacros | NeoMacros | Notes |
| --- | --- | --- |
| `JsMacros.on/once/off/waitForEvent` | `events.on/once/off/waitFor` | `UPPER_SNAKE` names become camelCase `domain:name`; the six cancellable events require `events.onSync` |
| `Chat` | `chat` | also gains `title`/`toast` |
| `Player` | `player` | |
| `World` | `world` | |
| `Client` | `client` | |
| `KeyBind` | `input` | |
| `Hud` (Draw2D/Draw3D) | `hud` + `render` | |
| `FS` | `fs` | natively async — `await` every call |
| `GlobalVars` | `storage` | |
| `Request` | `net` | |
| `Reflection` / `JavaUtils` / `JavaWrapper` | `java` + `reflect` | gated by the java permission |
| `Time.sleep(ms)` | `thread.sleep(ms)` | `Time.time()` was always `Date.now()` in the compat layer |
| `PositionCommon` | `Pos3D` and friends | |
| `Color` | plain ARGB integers | compat ships the same helpers today |

Two shape changes come with the move: event callbacks receive a single
payload object instead of `(event, context)`, and subscriptions made while
a script loads are tracked and unsubscribed automatically when the script
unloads — no manual cleanup for the common case.
