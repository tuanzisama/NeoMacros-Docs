---
title: "Migrating from JsMacros"
---

JsMacros and NeoMacros scripts share the language — plain ES modules —
not the API: `neo.*` facades replace the JsMacros globals, camelCase
`domain:name` event names replace `UPPER_SNAKE`, I/O is async-first, and
each script is a manifest-described folder. Two migration paths, freely
mixable:

- **Compat layer** — [jsmacros-compat](#compat-layer-installation)
  reimplements the JsMacros 1.9.2 script API on `neo.*`;
  `Player.getPlayer()`, `JsMacros.on('Tick', ...)` keep running with
  minimal changes.
- **Native rewrite** ([native API map](#native-api-map)) — the durable
  path; the compat layer makes it incremental, one script or one part at
  a time.

## Compat layer installation

1. The [compat pack](https://neomacros.tuanzi.ink/downloads/jsmacros-compat.zip)
   (~105 KB) extracts to a single `jsmacros-compat` folder.
2. The folder goes into the script root, `config/NeoMacros/macros/`. The
   data directory name follows the mod display name; pre-rename
   `config/neomacros` installs are not migrated.
3. Each script that uses the old API imports once at the top:

```js
import './jsmacros-compat/src/index.js';
```

The import mounts the full global surface — `JsMacros`, `Player`,
`World`, `Chat`, `Client`, `Time`, `KeyBind`, `Hud`, `FS`, `GlobalVars`,
`Request`, `Reflection`, `JavaUtils`, `JavaWrapper`, `PositionCommon`,
`Utils`, `Color` — idempotently: parallel imports from many scripts
mount once.

::note
The compat layer is a script-level library: no Java code, no files
outside the script folder; uninstall is folder deletion.
::

Editor and `tsc` support: `jsmacros-compat/types/jsmacros-compat.d.ts`
goes into the `tsconfig`.

## Script layout

The compat layer bridges the API surface, not the hosting model. JsMacros
executes every `.js` file in its scripts folder; NeoMacros loads one
folder per script, each with a `neomacro.yml` manifest, under a
trigger-type directory — `keypress/`, `event/`, or `services/` (see
[folder layout](../guide/getting-started)). Mapping:

- Top-level `JsMacros.on(...)` script with a game-session lifetime →
  `services/`; the self-registration style keeps working through the
  compat layer.
- Script that wakes only on declared events → `event` macro declaring
  them under `config.event.on` (see [Your First Script](../guide/first-script));
  body ported at convenience.
- Keybind script → `keypress/` with `key_code`, or the compat `KeyBind`
  surface.

## Coverage

- **Read surface** (synchronous, live handles): player/world/entity/block
  queries, `Chat.log/say/actionbar`, `Time.time()`, key injection via
  `KeyBind`, `GlobalVars` (backed by `storage`), the four-tier entity
  helper chain plus 75 specialized entity shells, the inventory surface
  plus 16 specialized inventory shells, `Color`, `PositionCommon`,
  base64 in `Utils`.
- **Event bridge**: `JsMacros.on/once/off/waitForEvent`, `(event, context)`
  callback shape, 36 bridged event names plus legacy `UPPER_SNAKE`
  aliases, per-event payload adapters, custom events, JS-side filterers.
- **Render**: `Hud.createDraw2D` (text elements), `Hud.createDraw3D`
  (boxes, lines, points), JsMacros register lifecycle included.
- **Escape hatches**: `Reflection`, `JavaUtils`, `Client.getMinecraft` —
  behind the NeoMacros java permission, like their JsMacros equivalents.

## Async surfaces

NeoMacros is async-first. These surfaces keep JsMacros signatures and
return promises:

| JsMacros call | Compat return |
| --- | --- |
| `FS.*` (all filesystem access) | `Promise<...>` |
| `Request.get/post/create(url).get()` | `Promise<ResponseCompat>` (its `text()/json()/byteArray()` are async) |
| `Time.sleep(ms)` | `Promise<void>` |
| `Client.waitTick([n])`, `Client.runOnMainThread(fn, true)` | `Promise<void>` / `Promise<unknown>` |
| `Inventory.click/dropSlot/quick/swapHotbar/split/grabAll/closeAndDrop/close` | `Promise<void>` |
| `ClientPlayer.dropHeldItem`, interaction-manager actions | `Promise<void>` |

::warning
An un-awaited `FS.exists(p)` inside an `if` is always truthy — the branch
checks the promise object, not the file. Call sites move one at a time,
not in batch.
::

## Missing surface

Members without a NeoMacros equivalent **keep their names and throw
`UnimplementedError`** on call — no silent absence; failure lands at the
exact call site. Highlights:

| Missing area | Detail |
| --- | --- |
| Packet access | JsMacros names unbridged; the native `packet:receive`/`packet:send` events, event-scoped `PacketBuffer`, and the `client.createPacketBuffer`/`sendPacket`/`packetIds` face carry the surface for direct use |
| `Title` / `SignEdit` events | JsMacros names unbridged; the native `chat:title`, `chat:actionbar`, `screen:signEdit` events carry the surface for direct `events` use |
| Inventory click events | The `ClickSlot` family — no inventory events |
| Custom screens & textures | JsMacros `ScriptScreen`/`FHud.createScreen` shells stay stub-backed; native `player.buildScreen` sessions, the screen builder family, and the `hud.texture` registry carry creation for direct use |
| Runtime Java compilation | Java source compilation at runtime |
| Specialized species states | The native species state tree is complete; compat shells predate it — reads beyond their bridge stay stub-backed |

The full list — 1,157 class-level members, 24 event-payload members, 19
unsupported event names, each with a documented reason — is
`docs/missing-apis.md` in the
[compat download](https://neomacros.tuanzi.ink/downloads/jsmacros-compat.zip).

## Behavioral deviations

No throws here — different behavior from JsMacros:

| Difference | What changes |
| --- | --- |
| FS path root | Paths resolve against the game directory, not the scripts folder |
| Entity reads are live | Helpers re-read through live handles instead of snapshotting at creation; vanished entities read as `null`/`undefined` |
| Display names | `getName`/`getDefaultName` derive from the id (`minecraft:deepslate_bricks` → `Deepslate Bricks`) — no translation lookup |
| `isDay` / `isNight` | Fixed vanilla window: night spans ticks 13000–23000 |
| Message rewriting | compat `RecvMessage.text` / `SendMessage.message`: reads work, assignment throws — the compat bridge has no write face; native `events.onSync('chat:send')` rewrites `e.message` directly |
| Custom events | Not cancellable |
| `ANYTHING` wildcard | Skips high-traffic events (`tick`, `world:sound`, `world:blockUpdate`) by default |
| `HeldItemChange.offHand` | Always `false` — held-item event fires for the main hand only |
| Styled text | `Chat.log` styled text renders via legacy `§` codes; hover/click styling dropped |
| World scans | compat `iterateSphere`/`iterateBox` are plain JS loops; native `world.scanBlocks`/`entity.inRadius`/`entity.inBox` run filtered scans as promises over per-tick slices |

Complete list: section 8 of `docs/missing-apis.md` in the
[compat download](https://neomacros.tuanzi.ink/downloads/jsmacros-compat.zip).

## Native API map

Retirement of the compat layer from a script is a mostly mechanical
mapping:

| JsMacros | NeoMacros | Notes |
| --- | --- | --- |
| `JsMacros.on/once/off/waitForEvent` | `events.on/once/off/waitFor` | `UPPER_SNAKE` names become camelCase `domain:name` (`key:press` is now `input:keyPress`); cancel and rewrite run on `events.onSync` — writable payload, `e.cancel()`, `neo.EventPriority` ordering |
| `Chat` | `chat` | plus `title`/`toast` |
| `Player` | `player` | typed open-screen snapshots via `player.screen` |
| `World` | `world` | |
| `Client` | `client` | |
| `KeyBind` | `input` | |
| `Inventory` | `player.inventory` | `items` is a `Record<number, ItemStack>` keyed by slot |
| `Hud` (Draw2D/Draw3D) | `hud` + `render` | Draw2D/Draw3D component families, `hud.texture` registry |
| `FS` | `fs` | natively async — `await` per call |
| `GlobalVars` | `storage` | |
| `Request` | `net` | |
| `Reflection` / `JavaUtils` / `JavaWrapper` | `java` + `reflect` | behind the java permission |
| `Time.sleep(ms)` | `thread.sleep(ms)` | `Time.time()` is `Date.now()` |
| `PositionCommon` | `Pos3D` and friends | |
| `Color` | plain ARGB integers | compat ships the same helpers |

Three shape changes: event callbacks receive a single payload object (no
`(event, context)` pair); async payloads are frozen snapshots, mutation
lives on `events.onSync`; subscriptions made during module load are
tracked and removed on module unload.
